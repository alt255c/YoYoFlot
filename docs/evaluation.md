# T20 · проверка исходного продукта

Автоматическая проверка использует исходные признаки, без создания новых
людей, перелётов, классов и разметки. evaluation.json сохраняет 12 сравнений:
пороги ×0.8/1/1.2, каждый вариант с тремя группами и с исключением каждой одной.
Для каждого — размер top и Jaccard к основному top50. Расчёт использует тот же
допуск наблюдений; изменяется только проверяемый параметр.

При наличии IF отдельно считается Jaccard top50 правил и IF. Это согласие
методов, не точность. combined_score сохраняется отдельно. Проверка качества
идентичности и исходной географии не подменяется совпадением двух рейтингов.

review.csv содержит выбранных людей и пустые reviewer/decision/reason.
Решения должен внести независимый проверяющий в копию CSV, сохранив исходный
снимок. Ревью не объявляется пройденным по факту генерации пустого файла.
Ground truth отсутствует, precision/recall и положительные метки не создаются.

pytest проверяет формулы, веса, неполноту, одинаковые дни, evidence,
границы top50, отсутствие генерации, целостность, кэш, HTTP и все карточки.
Тестовые минимальные примеры не используются продуктом. Старые synthetic
арифметические тесты сохранены как регрессия исторических модулей, отдельно
от подтверждения работоспособности на исходном наборе.

Полный запуск на поставленных LFS-таблицах и результаты браузерной проверки
фиксируются в docs/validation/source_product.json; они не доказывают полный
raw-прогон T16 или независимую предметную приёмку.

Для повторения числового аудита: `python scripts/verify_source_product.py`.
Команда читает существующий продукт, независимо пересчитывает формулы по
сегментам top50 и сверяет агрегаты объяснений со всеми сохранёнными баллами.
Она не создаёт профили, не дополняет исходные таблицы и не десериализует модель.
