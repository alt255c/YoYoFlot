# T20: метод проверки и запуск

Пакет 0.11.0; `evaluation-demo-1.0`; ветка `reape/T20` создана прямо от T19.
Автоматический опыт завершён технически; независимый аудит и T21 ожидаются.
M07 выключен, `ui_ready=false`. Поддерживаются только независимо вымышленные
истории с воспроизведением каждой строки. Реальные/переименованные персональные
входы и произвольный импорт модели не поддерживаются.

## Запуск

Из корня проекта в закреплённом окружении:

```powershell
uv sync --frozen --extra test
uv run --frozen python scripts/run_t20.py
```

В уже установленном окружении: `python scripts/run_t20.py`. T11–T19 повторять
не нужно. T20 сам создаёт учебные входы и необходимые родители T17/T18/T19;
**обучение IF выполняется** для заданных вариантов. Прежние реальные результаты
не читаются. Поддержаны PyCharm Run, другая рабочая папка и `-q`.

Конфигурация плана — `configs/evaluation.yaml`. Модель/правила/граф задаются
`--if-config`, `--rules-config`, `--graph-config`. Изменяйте копии конфигов,
а не исходные настройки для подгонки результата по holdout. Число вариантов,
профилей и диапазоны параметров ограничены. База требует все три travel-признака
и M01–M03, конец окна 31.03.2026 и выключенный граф; граф включается отдельным опытом.

Выход — `artifacts/t20/evaluation-<hash>/`, кэш — `data/work/t20/`.
`summary.txt` содержит путь, число опытов и состояние ревью. Повтор использует
только проверенные результаты. После Ctrl+C завершённые родители используются
снова; частичный верхний снимок не публикуется. Существующий чужой/повреждённый
выход не перезаписывается. Ключ включает код, Python и версии библиотек
обучения T19; смена sklearn/NumPy/SciPy/joblib меняет запрос T20. Каждый
родитель дополнительно проверяется на соответствие этому runtime.

## Наборы и заранее заданные метки

| Набор | Генератор / seed / размер | Назначение |
|---|---|---|
| Training | v2 / 101 / 300 | Fit T19; без меток сценариев |
| Calibration | v2 / 202 / 200 | Оба замороженных процентиля T19 |
| Holdout | independent-holdout-v1 / 303 / 120 | Отдельное семейство историй |
| Replicate | holdout / 404 / 120 | Другие количества поездок и география того же тестового семейства |
| In-domain | v2 / 505 / 120 | Проверка неразмеченного набора; качества по меткам нет |
| Цензурированный holdout | holdout-censored-v1 / 303 / 120 | Те же ID/сегменты, дополнительные неизвестные маршруты |

Новые генераторы реализованы отдельно от v2. Числа поездок варьируются в заранее
заданных диапазонах; правила не используются для присвоения метки. Gate
сверяет физические/логические хеши, схемы и все строки с рецептом. Метки
присоединяются в evaluation **после** вызова обучения, в матрицу не попадают.

Каталог содержит редкие обычные поездки, регулярные рабочие возвраты,
короткие поездки с возвратом, плотную активность, ежедневные обратные
направления, трёхзвенный цикл, медленные повторы и явную совместную серию.
Неизвестные даты, маршруты, покрытие и пустая история имеют метку null,
а не отрицательный класс. На 120 профилях: 42 заложенных тестовых случая,
38 контролей, 40 недостаточных историй. Два участника совместной серии
проверяются по явным событиям T18; одно общее расписание не объявляется встречей.

`benchmark_label=1` значит «предписанный стрессовый сценарий», а 0 — контроль
данного задания. Это не свойство личности, не универсальная истинная аномалия
и не вероятность. Рабочие/семейные истории могут совпадать с такими паттернами.
Повторный seed внутри одного семейства не заменяет внешнюю проверку на новых
семействах. Примеры зависимы внутри сценариев; статистические доверительные
интервалы/значимость улучшения не заявляются.

## План 21 опыта

Три опорных набора; два seed леса (1902/1903); 100/400 деревьев; подвыборка
64/256 (эффективно ограничена числом полных training); пороги ×0.9/×1.1;
вес правил 0.25/0.75; `as_of=2026-03-01`; поочерёдное отключение M01, M02,
M03 вместе с соответствующим IF-признаком; цензурированные маршруты; граф;
графовый seed 30; отдельный Monte Carlo seed 1802.

Опорный лес T19 — 200 деревьев, random_state 1901, max_samples 128, n_jobs 1.
Параметры, веса и основной режим после измерения не подбираются автоматически.
При изменении окна training, calibration и evaluation используют одну дату;
будущие сегменты сохранены, но не участвуют в признаках. Для изменённого окна
и цензурирования AP/ROC/P@K выключены: исходные полные сценарные метки не
используются как истины для другой наблюдаемой истории. Остаются покрытие и устойчивость.

## Метрики и сравнимые совокупности

Численный сравнительный набор — пересечение доступных профилей всех трёх
методов внутри одного опыта. Отдельно записываются весь вход, доступность
каждого метода, размер пересечения и число размеченных случаев каждого класса.
Недостаток опорного набора/выключенный IF оставляет основной топ правил,
но делает общее сравнение недоступным; баллы не заменяются нулём.

Правила упорядочиваются лексикографически по `(matched_criteria_count, rule_score)`.
Для AP/ROC это кодируется порядковыми уровнями с сохранением равенств.
Поле `score` правил в `scores.parquet` содержит балл правил, поэтому отдельно
от счётчика оно не задаёт приоритет. IF и комбинация используют баллы T19.
Основной фактический топ правил исключает `no_matches`; нулевой балл известного
сопоставимого профиля всё же участвует в AP/ROC. Он не считается пропуском.

AP — сумма приростов полноты × precision на уровнях одинакового балла,
без линейного сглаживания; ROC AUC учитывает половину веса равных пар.
Оба требуют в этом отчёте наличия обоих известных классов. P@K делится на
**реально выбранное** число строк, а не всегда на K; неизвестная метка в
выбранном топе делает precision недоступным. Рядом сохранены размеры и полнота.
Граница с равными баллами получает худший/лучший P@K при перестановке только
этой группы. Это диапазон состава топа, а не доверительный интервал.

Jaccard и Spearman между разными наборами profile_id не вычисляются.
Для тех же профилей есть end-to-end Jaccard опубликованных топов и Jaccard
после ограничения общей доступной группой с повторным выбором K. Записаны
вошедшие/выбывшие профили. Spearman использует средние ранги равных баллов,
без порядка по ID; меньше двух значений/константа дают null. Два пустых топа
тоже дают Jaccard null, а не ложную полную стабильность.

Абляции дополнительно оцениваются **попарно на одном пересечении** базы и
варианта (`paired_comparison.csv`). Это исключает улучшение из-за молчаливого
удаления трудных строк. Разница метрик на этом benchmark не является доказанным
причинным вкладом признака или основанием изменить основную модель.

| `review/blind/` | Истории, качество и контекст событий с непрозрачными ID, без баллов/меток |
| `review/ranking_audit.csv` | Пустые поля решений проверяющего |
| `private/audit_key.parquet` | Ключ, страты и скрытые метки; проверяющему не передавать |
| `report.json`, `summary.txt`, `run_manifest.json` | Статус, ссылки/хеши, полный состав и неизменяемый run_id |

Схемы 1.0 определены в `evaluation/artifact.py` и `audit.py`.
Новые таблицы имеют metadata synthetic_demo/run_id; ссылки на T19 и скопированные
T17 сохраняют собственные идентификаторы. Корректность фиксируется полным
составом/хешами и повторным воспроизведением входов, а не одинаковым run_id всех таблиц.

Старые joblib-файлы при проверке T20 и импорте ревью не загружаются. Только
T19 читает свой только что сохранённый файл при fit. Хеши обеспечивают целостность,
а не удостоверяют автора; ограничения формата сохраняются из [T19](model_card.md).

## Ручное ревью

По умолчанию выбираются 50 уникальных историй: цели 50% из объединения топ-50,
30% вне топов, 20% недостаточных данных. При нехватке страты остаток заполняется
из ещё не выбранных историй; фактический состав указан явно. Выбор не является
случайной выборкой по всей совокупности. Положительная доля решений в нём не
называется precision модели.

Передайте проверяющему **только** `review/blind/` и копию CSV. Исходные ID,
ранги, методы, страты и каталог меток остаются закрытыми до завершения ревью.
Знание генератора может нарушить слепоту; непрозрачные ID не являются защитой
от проверяющего, который специально восстановит весь генератор.

Сохраните заполненную копию вне неизменяемого снимка, например в
`data/work/t20-review/reviews.csv`. Поля: `review_id`, `reviewer`, `verdict`,
`reason_ru`, `reviewed_at`. Вердикты: `интересно_проверить`, `обычная_история`,
`недостаточно_данных`; дата ISO с поясом. Полностью пустое решение остаётся
ожидающим. Частичные строки, неизвестные ID/вердикты и дубли вызывают ошибку.

```powershell
python scripts/audit_t20.py --input artifacts/t20/evaluation-<hash> --reviews data/work/t20-review/reviews.csv
```

Ответы сохраняются отдельным неизменяемым отчётом с хешами в `artifacts/t20-review/`.
Даже полностью заполненный CSV не удостоверяет личность/независимость автора и
не выдаёт T21 pass. Автоматически заполненных решений в поставке нет.

## Независимая проверка реализации

```powershell
python scripts/verify_t20_demo.py
python -m pytest -q
```

Verifier создаёт собственный свежий опыт, затем считает AP по группам порогов,
AUC перебором положительных/отрицательных пар, P@K и диапазон равенств по
сохранённым таблицам. Производственный metrics-helper не вызывается, pickle
не читается. Сверяются CSV/JSON, проекции родителей, исходные топы и пустой аудит.
Протокол и свежий снимок — в `data/verification/`. Короткая публикация измерений
есть в [reports/t20](../reports/t20/README.md), проверки — в
[протоколе T20](validation/t20_validation.json).

Формулы API сверены с [sklearn AP](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html),
[sklearn ROC AUC](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_auc_score.html),
[SciPy Spearman](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.spearmanr.html).
Качество за пределами этих семейств, условия графового фона и независимое
содержательное ревью остаются ограничениями. Основной режим/пороги не меняются;
IF и граф могут не улучшать правила — это допустимый результат проверки.
