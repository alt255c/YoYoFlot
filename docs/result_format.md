# Результат DS backend без веб-интерфейса

Команда читает завершённый снимок продукта, проверяет его контрольные суммы и
экспортирует уже рассчитанный топ-50, факторы и географию:

```bash
python -m yoyoflot report \
  --product artifacts/source-product \
  --output artifacts/source-product-report
```

CLI показывает первые 10 позиций; все результаты находятся в каталоге отчёта.
`-q` отключает консольную сводку. Веб-сервер не требуется.

| Файл | Содержание |
| --- | --- |
| `report.md` | Русское описание методики, покрытия, ограничений и таблица всего топа |
| `top50.csv` | Место, ID/имя, сработавшие и доступные критерии, балл, число сегментов и покрытие географии |
| `factors.csv` | По одной строке на профиль и критерий: факт, порог, вес, вклад, статус, причина недоступности, калибровка и свидетельства |
| `flights.csv` | Все сегменты выбранных профилей: аэропорты и координаты, даты/время и точность, статусы, ссылки на исходные строки |
| `profiles.json` | Полные профили `ProductStore`: `person`, `factors`, `segments`, `route_balance`, `source_evidence`, `companions`, `additional_factors` |
| `summary.json` | Счётчики, окно дат, покрытие факторов для всей популяции и топа, происхождение и статус raw-прогона, методика, оценка, ограничения и компактный топ |
| `report_manifest.json` | `run_id`, хеш исходного манифеста, запрос/хеши снимка и SHA-256 всех файлов отчёта |

`run_id` связывает все CSV и JSON с одним проверенным снимком.
В `summary.json` поле `source_provenance` указывает режим входа, core ID и
статус проверки raw. Если вспомогательный XLSX coverage был восстановлен,
`source_provenance.auxiliary_repair` сохраняет исходный core ID, SHA родительского
манифеста и repair manifest, статус и точный объём исправления. В снимке продукта
также сохранены манифест ремонта, исходный manifest и отчёты проверки; исходные
canonical/resolution-таблицы при таком исправлении не меняются. Отдельный статус
независимого человеческого ревью остаётся `pending`.

`person_id` связывает профиль с факторами и перелётами. `segment_id` и
`anchor_travel_id` сохраняются даже при отсутствии ссылок на первичные строки.
В `factors.csv` поле `evidence_segment_ids_json` содержит JSON-массив ID
связанных сегментов, `source_evidence_json` — исходные ссылки сегментов или наблюдений, подтверждающих фактор этого профиля. В `flights.csv` `source_evidence_json` относится
только к текущему сегменту, `related_criteria_json` перечисляет связанные критерии.
Поля `*_json` разбираются JSON-парсером после чтения CSV.

Недоступный фактор имеет `status=unavailable`, причину в
`availability_reason` и нулевой вклад. Это не означает отсутствие признака.
Числа доступных и всех факторов показаны отдельно. Координаты неизвестных
аэропортов остаются пустыми, `is_plottable=False`, причина указана в
`unplottable_reason_ru`; сам сегмент не исключается. Статусы поездки, разрешения
идентичности и точность дат сохраняются без вывода о фактической посадке.

CSV имеет кодировку UTF-8 с BOM и разделитель `,`. Пустая ячейка означает
неизвестное значение. Для безопасного открытия в Excel строковые значения,
похожие на формулы, получают ведущий апостроф **только в CSV**. JSON содержит
исходные строковые значения без такого преобразования. Числовые поля остаются
числами, в JSON неизвестное значение — `null`.

Экспорт не пересчитывает факторы и не создаёт исходные наблюдения. Он
сохраняет порядок снимка. Баллы не являются вероятностью класса; без
подтверждённой разметки precision/recall не заявляются. Isolation Forest удалён. Связи совместных поездок сохраняются в карточках.

Одинаковая повторная команда проверяет файлы и возвращает тот же отчёт.
Для другого снимка, версии экспортёра или изменённого отчёта нужен новый путь.
Чужой/повреждённый каталог не перезаписывается. Отчёт нельзя размещать внутри
снимка, на месте снимка или в его родительском каталоге. Публикация происходит
после завершения файлов и повторной проверки снимка; прерванная запись не
оставляет завершённый каталог.
