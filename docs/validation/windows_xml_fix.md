# 0.3.2: аварийное завершение при XML на Windows

Пользовательский запуск: T05/T06 прошли, во время обработки T07 процесс завершился
с 0xC0000374, без Python traceback. Этот код Windows означает повреждение кучи;
сам по себе он не устанавливает виноватую библиотеку.

В reader обнаружена небезопасная операция parent.remove(user) для текущего
узла iterparse. Документация lxml запрещает удалять текущий узел/его предков.
Теперь user.clear(keep_tail=True) очищает содержимое, а удаляются только
предыдущие завершённые siblings. Первичные ключи, связи и формат не меняются.
Ссылка на первоисточник: https://lxml.de/parsing.html#modifying-the-tree

check_all_data.py запускает ingest, проверки таблиц, PDF-экспорт и независимые
census/audit в отдельных процессах того же интерпретатора. Нативный сбой worker
фиксируется с exit code/hex и не уничтожает supervisor: следующие источники
продолжают проверяться. JSON-отчёт сохраняется после каждого источника.
PYTHONIOENCODING=utf-8 и faulthandler включены у workers; их сообщения остаются
в verification.log, запросы/результаты — data/verification/workers.

CSV/JSON с совпадающим SHA-256 и полными таблицами повторно не парсятся.
Их схемы/ссылки проверяются снова отдельным worker. Нельзя ставить passed
источнику, чей worker завершился с ненулевым кодом, даже если файл отчёта существует.

Новые проверки: текущий XML-узел остаётся присоединённым; код 0xC0000374
распознаётся как ошибка worker; реальная цепочка дочерних ingest/validate работает.
Всего 64 теста на Linux/Python 3.12. Нативный Windows/Python 3.10 здесь недоступен;
что именно повредило кучу на пользовательской машине, без native dump не доказано.
Зависимости прежние, версия пакета/lock обновлена до 0.3.2.

Пользователю достаточно заменить файлы проекта из архива, сохранив .git/.venv/data,
и снова нажать Run для check_all_data.py. Существующие корректные результаты
будут проверены; незавершённый XML будет обработан заново.

Полный повтор XML в отдельном worker завершён: 66657 пользователей, 88818 карт,
436090 активностей, errors=0. Все шесть таблиц полностью совпали с предыдущим
проверенным проходом (EXCEPT ALL в обе стороны). 912 сверок исходных значений
также прошли через дочерний audit-worker. Тест аварии XML подтверждает сохранение
ошибки и продолжение T08/T09/T10 в supervisor.
