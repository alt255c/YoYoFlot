# Исправление Windows / Python 3.10: версия 0.3.1

По пользовательскому логу: 8 failed, 34 passed, Windows/Python 3.10.11,
установленный пакет 0.2.0. PDF-тесты отдельно: 4 passed.

Причины: sqlite3.Connection как context manager управляет транзакцией, но не
закрывает соединение. Временный keys.sqlite оставался открыт, Windows не мог
удалить каталог, ошибка очистки маскировала исходное исключение. JSON/YAML теперь
используют contextlib.closing для соединений и внутренних генераторов, включая
ошибки вложенных объектов и досрочное закрытие reader.

Тестовые JSON/Sirena с кириллицей записывались в системной кодировке Windows,
а readers ожидали UTF-8. Теперь текстовые файлы читаются и записываются явно
с encoding=utf-8; это также исправлено в scripts и чтении PDF checkpoint.
Подпроцессы сквозного примера принудительно передают UTF-8 для stdin/stdout.

Добавлены 7 сценариев SQLite: завершение, повтор ключа, повтор поля внутри
профиля и досрочное закрытие. Они проверяют, что соединение закрыто ДО удаления
временного каталога, моделируя ограничение Windows. Полный набор: 57 passed.
Также выполнен запуск с EncodingWarning как ошибкой; исключена только известная
запись временного файла внутри openpyxl, не использующая текстовые данные проекта.
Текстовые Path read/write вызовы проверены на явный encoding.

Среда проверки Linux/Python 3.12.14. Нативный Windows/Python 3.10 прогон здесь
недоступен; его результат не заявляется. Зависимости прежние, lock/requirements
согласованы с версией 0.3.1. Изменения не меняют значений реальных таблиц,
полные данные предыдущей версии заново не обрабатывались.

## Установка на Windows

Заменить файлы проекта содержимым этого архива, сохранив .git, .venv и data.
Из корня выполнить:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
.\.venv\Scripts\python.exe -m yoyoflot --version
.\.venv\Scripts\python.exe -m pytest -q
```

Ожидаемая версия yoyoflot 0.3.1, число тестов 57. PYTHONUTF8 не требуется.

## Дополнение: кодировка CLI subprocess

По следующему Windows-прогону 56 тестов прошли, один тест CLI падал:
справка дочернего процесса выводилась в системной кодировке, а тест читал UTF-8.
Теперь test_cli.py передаёт PYTHONIOENCODING=utf-8 дочернему процессу, сохраняя
остальные переменные окружения. CLI-тесты также проходят при установленной
родительской PYTHONIOENCODING=cp1252.
