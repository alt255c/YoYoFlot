# 0.3.3: совместимый запуск PDF и видимый прогресс

Причина отсутствия результата при привычном Run: readers/timetable_pdf.py был
только import alias, без выполнения process в __main__. Теперь он сохраняет
импортную совместимость и запускает обработку при Run. bootstrap src исключает
зависимость такого запуска от pip install -e. Рабочая папка PyCharm не важна.

Настройки файла: PDF_PATH (None — поиск data/Skyteam_Timetable.pdf и data/raw),
OUTPUT_DIR по умолчанию data/interim/timetable_pdf, CHUNK_PAGES=100.
Командная строка необязательна; флаги --path/--output также поддержаны.

Во время разбора сохраняются соседний *.checkpoint/checkpoint.json, порции JSON
и page_*.txt. CSV/JSONL/Parquet публикуются после прохода и сборки. Прежний финальный
результат сохраняется до успешной публикации нового. Печатаются число страниц,
завершённые порции, стадия выгрузки, конечный путь и JSON-отчёт. Импортный API/CLI
по умолчанию сохраняет машинно читаемый stdout без прогресса. check_all_data.py
включает прогресс только внутри PDF-worker; его путь data/interim/real/timetable_pdf.

Старый checkpoint без signature сбрасывается корректно вместо KeyError. Это
может потребовать полного повторного прохода, потому что прежние неверсированные
порции нельзя смешивать с текущим контрактом. Семантика parse_page не изменена.

Исправлен PDF audit-worker: audit(n=50, out=output) вместо конфликтующего
позиционного вызова audit(output,n=50). Уже заполненный audit_sheet не заменяется.

Проверены прямой запуск из другой cwd, все три выходных формата и сообщение
прогресса; восстановление старого checkpoint; ingest + PDF-check + создание
пустой ручной выборки в дочерних процессах. Всего 67 тестов на Linux/Python 3.12.
Сам выданный PDF отсутствует; полный реальный прогон и Windows-прогон не заявлены.
