# T11: повторный запуск после остановки

Патч применяется поверх YoYoFlot 0.4.0: распаковать в корень проекта
с заменой файлов, включая новый normalize/locking.py. Зависимости прежние.

Факт существования .t11.lock больше не блокирует работу. Используется
неблокирующая системная блокировка (msvcrt на Windows, flock на Unix).
Пустой файл от прежней версии совместим; удаление вручную не нужно.
Файл остаётся на диске после успешного запуска; не коммитить и не удалять
во время работы процесса. Если другой процесс действительно работает,
второй запуск отклоняется с понятным сообщением.

Ctrl+C обрабатывается без traceback, код завершения 130. Перезапуск начинает
проход с начала; восстановления checkpoint у T11 пока нет. Прежние готовые
результаты не заменяются до успешной сборки.

При долгом запуске прогресс печатается не чаще раза в 30 секунд, на границах
порций/этапов; это не строгий heartbeat во время одного длительного вызова.
-q/--quiet сохраняет пустой успешный консольный вывод. Итог остаётся
в консоли и geography_summary.txt без -q, только в файле с -q.

Проверка: 139 тестов прошли на Linux/Python 3.12, включая сохранность прежнего
результата после KeyboardInterrupt, повторный запуск с пустым старым lock,
конкуренцию отдельных процессов, освобождение после принудительного kill,
тихий CLI и progress callback. Нативный Windows-прогон здесь недоступен.
Дополнительно вставки seen_travels объединены в executemany по порции;
это сохраняет проверку уникальности ID, отдельное ускорение не измерялось.
