# Запуск T20 (пакет 0.11.0)

`python scripts/run_t20.py` выполняет 21 заранее заданный учебный опыт с IF,
правилами и графом. Предыдущие реальные этапы повторять не требуется.
Путь к результату — в summary; по умолчанию `artifacts/t20/evaluation-<hash>/`.
Реальные индивидуальные входы не поддерживаются. Подготовлены 50 слепых историй
с незаполненными решениями; T21 и интерфейс ожидаются.

```powershell
python scripts/run_t20.py
python scripts/verify_t20_demo.py
python scripts/audit_t20.py --input artifacts/t20/evaluation-<hash> --reviews data/work/t20-review/reviews.csv
```

Первая команда обучает варианты IF, вторая создаёт новый опыт и независимо
сверяет сохранённые метрики, третья читает заполненную внешнюю копию CSV.
Обычный повтор проверяет готовый кэш и не читает модели через pickle.
Скопируйте CSV из снимка перед заполнением: исходный снимок неизменяемый.
Полный порядок работы, конфиги, схемы и ограничения — [метод T20](evaluation.md).

# Запуск T19 (добавлен в пакете 0.10.0)

Ветка `reape/T19` создана непосредственно от `reape/T18`. Из корня проекта:

```powershell
uv sync --frozen --extra test
uv run --frozen python scripts/run_t19.py
```

В уже установленном совместимом окружении достаточно:

```powershell
python scripts/run_t19.py
```

**Этот запуск действительно начинает обучение Isolation Forest**. Он создаёт
независимо вымышленные наборы: training 300/seed 101, calibration 200/seed 202,
evaluation 120/seed 17. Пересчитывать реальные T11–T16 и прежние T17/T18 не нужно.
Вложенные учебные правила и при явном включении граф строятся автоматически.
Скрипт работает из другой рабочей папки и через PyCharm Run; `-q` отключает
успешный вывод, итог остаётся в файлах.

Выход — `artifacts/t19/if-<hash>/`, рабочий кэш — `data/work/t19/`.
В `summary.txt`/`report.json` видно, выполнен ли fit и сколько профилей
получили оценки. При малом/вырожденном опорном наборе или `enabled=false`
основной рейтинг сохраняется, но модель отсутствует, IF/комбинация — null.
Технически законченный опыт не означает T20/T21 pass.

```powershell
python scripts/run_t19.py --profiles 500 --seed 42
python scripts/run_t19.py --input artifacts/t17/rules-<hash>/input
python scripts/run_t19.py --help
```

`--input` принимает только воспроизводимый вымышленный вход, не файлы реальных
историй. Для старого v1-оценочного набора опорные v2 создаются автоматически.
`--reference` и `--calibration` задают отдельные учебные наборы; их seed и ID
должны отличаться от evaluation и друг от друга.

Настройки IF: `configs/isolation_forest.yaml`; правила:
`configs/model.yaml`. Для опыта с графом сделайте отдельную копию IF-конфига,
установите `include_graph: true` и передайте `--config <копия>`; графовые
параметры читаются из `configs/graph.yaml` или `--graph-config`. Даты `as_of`
должны совпадать. По умолчанию граф выключен, M07 не добавляет голос.

Повторная команда использует только проверенный снимок; существующие
несовместимые результаты не перезаписываются. Произвольный файл модели через
CLI не импортируется. Зависимости для сохранённого joblib фиксируются lock-файлом.

Дополнительная проверка создаёт **собственный новый** опыт и независимо сверяет
сохранённые float32-матрицы, sklearn-оценки, процентили, топы, хеши и основной рейтинг:

```powershell
python scripts/verify_t19_demo.py
python scripts/verify_t19_demo.py --profiles 500 --report data/verification/t19_500.json
python scripts/verify_t19_demo.py --include-graph --report data/verification/t19_graph.json
python -m pytest -q
```

Она не принимает путь к чужому pickle. JSON-протокол и свежие снимки остаются в
`data/verification/`, в Git они не добавляются. Метод, точные схемы и ограничения:
[карточка модели](model_card.md); [проверки автора](validation/t19_validation.json).

# T16: воспроизводимый запуск ядра данных

Добавлено в версии 0.7.0; доступно в 0.8.0. T16 возобновлена по указанию пользователя 17.10.2026.
Работа ведётся в `reape/T16` от `develop`; изменения плана интерфейса остаются
отдельно в `reape/update`.

T16 объединяет существующие этапы: readers → T12 → T11 → T13 → T14 →
завершённый снимок. **Модель, рейтинг людей, T15 и веб-интерфейс не запускаются.**
Снимок имеет `scope=internal_data_core`, `ui_ready=false`, `model_built=false`;
его техническое завершение не заменяет независимую приёмку и не разрешает
публикацию индивидуальных историй реальных людей. Учебный персональный интерфейс
и реальные агрегаты относятся к отдельным требованиям следующего этапа.

## Запуск на уже готовых T11–T13

Из корня репозитория, в существующем виртуальном окружении:

```powershell
python scripts/run_t16.py --from-processed data/processed --require-all --allow-source-errors
```

Этот вариант **не повторяет** readers, T12, T11 и T13. Он проверяет опубликованные
манифесты и SHA-256 всех их файлов, схемы/счётчики, конфигурации, справочник
и соответствие T13 конкретным T11/T12. Затем выполняет T14 и сохраняет отдельную
копию снимка. Исходный `data/processed` не изменяется; соседние результаты T15
не включаются в T16 и не удаляются.

`--allow-source-errors` нужен для известного неполного PDF и сохранённых ошибок
его разбора. Ограничения переносятся в итог, а не скрываются. Этот флаг
**не пропускает** нарушения схем/ключей/связей, неверные хеши, смешение версий,
ошибки нормализации T12 или блокеры T14. Если исходные отчёты не содержат ошибок,
флаг можно не указывать. Несовместимый комплект требует исправить именно
соответствующий upstream, а не отключать проверку целостности.

В этом режиме манифест честно указывает `raw_files_verified=false`:
перепроверены переданные готовые таблицы, а не оригиналы исходников.
Полная независимая приёмка многомиллионного набора здесь не заявляется.

## Полный запуск из исходников

```powershell
python scripts/run_t16.py --require-all
```

По умолчанию используются `configs/sources.yaml` и `data/raw`. Если неполнота
PDF уже изучена и её нужно сохранить как ограничение:

```powershell
python scripts/run_t16.py --require-all --allow-source-errors
```

Для исходников в другой папке добавляется `--data-dir <папка>`.
Отсутствующий обязательный файл вызывает ошибку; молчаливого пропуска источника
или перехода на маленькую выборку нет. `--require-all` требует все семь
логических источников и соответствующие отчёты/покрытие T13.

Альтернативный CLI:

```powershell
python -m yoyoflot run --config configs/sources.yaml --until build --require-all
```

В этой команде `--until build` означает **всё ядро до T14 включительно**.
Отдельная старая команда `python -m yoyoflot build` по-прежнему выполняет только
T12. Другие значения `--until` пока не поддерживаются; полный запуск модели
из старого целевого плана остаётся будущей интеграцией.

## Из готовых результатов readers

```powershell
python scripts/run_t16.py --from-interim data/interim/real --require-all --allow-source-errors
```

В указанной папке ожидаются каталоги семи readers с шестью Parquet-таблицами
и `source_report.json`. Проверяются контракт, источник, счётчики, схема и
конфигурация колонок Sirena. T12–T14 выполняются с обычным кэшем.
Оригиналы raw не перечитываются; это отдельно отражается в манифесте.
`--from-interim` и `--from-processed` взаимоисключающие.

## Короткий учебный прогон

```powershell
python scripts/run_t16.py --config configs/sources_fixture.yaml --data-dir tests/fixtures --work-dir data/work/t16_demo --require-all
```

Это полный проход семи вымышленных fixtures, не проверка реального набора.
Ожидаются 9 наблюдений людей, 13 идентификаторов, 9 наблюдений поездок,
5 строк расписания, 6 объединённых профилей и 9 сегментов. Время этого примера
не используется для прогноза длительности полного набора.

## Что сохраняется

| Путь | Содержимое |
|---|---|
| `data/work/t16/interim/<source>/` | Кэш readers и собственные PDF-checkpoints при запуске из raw |
| `data/work/t16/processed/` | Рабочие T12/T11/T13; в режиме `--from-processed` читается переданный каталог |
| `data/work/t16/quality/` | Аудит T14 и отдельная выборка для ручного разбора |
| `data/work/t16/pipeline_state.json` | Завершённость, подписи и SHA-256 выходов каждого этапа |
| `data/work/t16/logs/<id>.jsonl` | Журнал одной попытки: этапы, ход, переиспользование, ошибки |
| `data/work/t16/last_run.json` | Результат последней попытки и путь снимка |
| `data/work/t16/last_failure.json` | Последняя ошибка как историческая диагностика; после успеха ориентироваться на `last_run.json` |
| `artifacts/data-<fingerprint>/run_manifest.json` | Завершённость, ограничения, время выполнения, параметры, источники, количества, SHA-256 всех файлов |
| `artifacts/data-<fingerprint>/input_manifest.json` | Фактические входы, размеры/хеши и границы проверки оригиналов |
| `artifacts/data-<fingerprint>/environment.json` | Python, ОС, версии библиотек, версия пакета и хеши исходного кода |
| `artifacts/data-<fingerprint>/timings.json` | Проверка входов, длительность/переиспользование этапов и сохранение снимка |
| `artifacts/data-<fingerprint>/tables/` | Точные выходы T12/T11/T13 с их манифестами, отчётами и замороженной выборкой T13 |
| `artifacts/data-<fingerprint>/configs/`, `reference/` | Использованные конфигурации, справочник, его исходный файл и лицензия |
| `artifacts/data-<fingerprint>/quality.json`, `quality.md` | Проверка T14; отсутствие независимого ревью не маскируется |
| `artifacts/data-<fingerprint>/sources/` | При доступных readers — отчёты и вспомогательные coverage/page-text файлы |

Raw-файлы не дублируются в снимок. Для воспроизведения ingestion они нужны
отдельно в той же версии; их хеши/параметры сохранены. При переносе нестандартного
конфига с абсолютными путями нужно явно указать новые пути к этим входам;
сам факт копирования снимка не восстанавливает отсутствующие оригиналы.

Снимок создаётся в соседнем временном каталоге и появляется целиком только
после проверок. `--output <новая_папка>` позволяет задать его имя. Существующий
снимок нельзя перезаписать: для другого кода, параметров или входов выбирается
новая папка; без `--output` имя вычисляется автоматически. Все копии независимы
от рабочих файлов — последующий пересчёт не изменяет старый снимок.
Для автоматических имён `--artifacts-dir <папка>` задаёт общий каталог снимков.
CLI по умолчанию использует `artifacts` текущей папки, а скрипт/PyCharm —
`artifacts` в корне проекта, независимо от рабочей папки IDE.

## Повторный запуск и ограничения

Повтори **ту же команду**. T16 проверит хеши и пропустит подтверждённые этапы.
Если готовый снимок уже существует, проверит его целиком. Если выполнение
остановлено, продолжит с первого непригодного этапа; незавершённый T12/T11/T13
пересчитывается целиком. PDF дополнительно использует собственный checkpoint.
Построчного возобновления DuckDB-стадии здесь нет.

Подпись этапа учитывает входные байты, параметры, конфигурацию, код и окружение.
Изменение правил T12 не перечитывает raw; география может быть переиспользована,
если фактические входные строки и её собственные настройки остались прежними.
Изменение кода/окружения инвалидирует кэш консервативно. Размер и mtime не
заменяют SHA-256. Проверка больших таблиц тоже занимает время диска.

Прерывание Ctrl+C возвращает код 130 и освобождает OS-блокировку. Сам файл
`.t16.lock` остаётся: наличие файла не означает, что процесс ещё работает.
Одновременно писать в один рабочий каталог нельзя. Обычная ошибка — код 1;
ошибка аргументов — 2. Технически завершённый прогон, в том числе с явно
сохранёнными ограничениями, — 0. `-q` скрывает успешный вывод; диагностика
ошибок и журналы остаются.

`--memory-limit` по умолчанию `1GB` ограничивает DuckDB, а не всю память Python.
Этапы запускаются последовательно; T14 использует собственный временный каталог
для spill, удаляемый после закрытия базы. Для полного прохода нужно место
под рабочие таблицы, временные файлы и ещё одну копию готового снимка.
В режиме принятия готовых T11–T13 размер кэша меньше, но копия снимка всё равно
создаётся. Измеренного времени/RSS полного реального T16 пока нет.

## Справочник в старом checkout

`.gitattributes` закрепляет CRLF для `data/reference/airports.csv`: это байты,
на которые уже рассчитан опубликованный манифест. Данные и ожидаемая контрольная
сумма не меняются. Для нового Git checkout преобразование выполняется Git
([документация атрибута eol](https://git-scm.com/docs/gitattributes)).

Если старый клон сохранил LF после обновления, для **неизменённого вами**
репозиторного CSV можно обновить только его рабочее представление:

```powershell
git checkout-index --force -- data/reference/airports.csv
```

Проверка не отключается: содержательное изменение CSV по-прежнему требует
новой согласованной версии справочника и upstream-результатов.
