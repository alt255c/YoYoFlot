# YoYoFlot Sentinel · инструкция по запуску

YoYoFlot Sentinel — локальная веб-морда для просмотра результатов готового
product snapshot. Она показывает топ-50/100/1000, список всей популяции,
карточку профиля, факторы, evidence и карту маршрутов.

В блоке **«Перелёты профиля»** кнопка **«Запустить перелёты»** последовательно
показывает маршруты выбранного периода по датам, включая другие страницы списка.
Следующий маршрут выбирается после прибытия комарика к конечной точке.
После последнего перелёта показ останавливается. Записи без координат
пропускаются, их число указано рядом с кнопкой. Кнопка **«Остановить перелёты»**
останавливает движение и очередь; новый запуск начинает показ сначала.
Ручной выбор перелёта, смена профиля или периода также прекращает очередь.
Масштабирование и перемещение карты сохраняют ход полёта.
Перелёт выбирается нажатием на линию, наконечник стрелки или строку истории;
для стрелок также доступны Tab и Enter/пробел.

Если в проверенно связанных записях указан `Female` и нет противоречащего
`Male`, по карте летит муха с прозрачным фоном. При отсутствии пола персонаж
выбирается по справочнику имён из самого датасета: используются явные поля
`PassengerFirstName`, встречающиеся только с одним полом минимум в трёх
различных сочетаниях полного имени и даты рождения. Имя и фамилия могут стоять в любом порядке;
неоднозначные имена не определяют персонажа. На карте такой выбор помечен
как выбор по имени. При противоречии пола или отсутствии подсказки остаётся
комарик. Это только оформление: поле `sex` не заполняется по имени, маркеры
и баллы не меняются. Оба персонажа имеют размер 40 экранных пикселей.
Пол читается при открытии профиля из исходного `observations.parquet`.
Snapshot не пересобирается.
Локально путь берётся из манифеста дополнения; при переносе его можно задать
через `YOYO_PROFILE_OBSERVATIONS`. SHA-256 должен совпадать с входом дополнения.
В Docker этот файл монтируется только для чтения; путь на хосте задаётся через
`YOYO_PROFILE_OBSERVATIONS_PATH`. API возвращает `person.sex`, `sex_status`
и отдельный `map_mascot` с видом персонажа и основанием выбора.

Веб-сервис **не запускает тяжёлый raw-прогон из браузера**. Ему нужен уже
собранный и проверенный каталог продукта с `run_manifest.json`.

## 1. Подготовка на Windows

Откройте PowerShell в корне репозитория:

```powershell
cd C:\Users\dv-te\Desktop\DS\yoyoflot
```

Создайте окружение и установите пакет:

```powershell
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install --upgrade pip
& .\.venv\Scripts\python.exe -m pip install -e .
```

Если окружение уже создано, повторять эти команды не нужно.

## 2. Сборка snapshot из данных репозитория

**Если `artifacts/source-product/run_manifest.json` уже существует, для обычного
запуска веба переходите к разделу 3. Повторять `run_t17.py` после правок интерфейса
или backend не нужно.**

В текущем `develop` файлы `persons.parquet` и `segments.parquet` хранятся через
Git LFS. Сначала скачайте их:

```powershell
git lfs install
git lfs pull origin develop
```

Проверьте, что это реальные файлы, а не LFS-указатели:

```powershell
Get-Item .\data\processed\persons.parquet, .\data\processed\segments.parquet |
  Select-Object Name, Length
```

Затем соберите product snapshot из поставленных T13-таблиц:

```powershell
& .\.venv\Scripts\python.exe scripts\run_t17.py `
  --output artifacts\source-product
```

Команда использует реальные таблицы из `data\processed`, не создаёт людей,
перелёты или метки. Полный расчёт может занять несколько минут и требует
свободного места под производные таблицы.

Ошибка `Output belongs to another input/config/code version` означает, что
каталог результата уже занят snapshot другой версии. Команда не перезаписывает
его. Хеш `code` учитывает все Python-файлы проекта, включая backend, поэтому
правки веба могут вызвать это сообщение при повторной сборке. Существующий
проверенный snapshot можно по-прежнему использовать для запуска веба.
Если требуется именно новый расчёт, укажите новый, ещё не существующий каталог,
например `--output artifacts/source-product-rebuilt-20261022`. Дополнения
`source-assessment` привязаны к хешу продукта: старые дополнения нельзя просто
скопировать к новому продукту, их потребуется пересчитать для него.

## 3. Запуск на собранном snapshot

После предыдущего шага каталог создаётся автоматически. В нём должны быть:

```text
run_manifest.json
tables\rankings.parquet
tables\persons.parquet
tables\segments.parquet
```

Запуск из корня репозитория:

```powershell
$product = (Resolve-Path .\artifacts\source-product).Path
& .\.venv\Scripts\python.exe -m yoyoflot.product.web --product $product
```

После сообщения с портом откройте:

```text
http://127.0.0.1:8501/
```

Остановить сервер можно сочетанием `Ctrl+C`.

### Изменение весов без пересборки исходных данных

Редактируйте **`configs/scoring.yaml`**, раздел `weights`, затем остановите
backend, запустите его заново и обновите страницу браузера. Frontend обслуживается
тем же процессом; отдельного сервера для него нет.

```powershell
& .\.venv\Scripts\python.exe -m yoyoflot.product.web `
  --product .\artifacts\source-product `
  --scoring .\configs\scoring.yaml
```

Без `--scoring` используется `YOYO_SCORING_CONFIG`, затем `configs/scoring.yaml`
в текущем каталоге или каталоге исходного проекта. Запуск из другой директории
может потребовать абсолютный путь. Для установленного пакета вне checkout
передайте свой конфиг явно. Ошибка или отсутствие файла останавливает запуск;
сервер не подменяет его прежними весами.

- Допустимы все 12 известных ключей и конечные числа от 0 до 1000. Повторные,
  неизвестные или пропущенные ключи, отрицательные веса и `NaN` запрещены.
- `0` отключает баллы и участие фактора в числе сигналов рейтинга. Исходный
  результат проверки сохраняется; доступность данных от веса не зависит.
- M01–M03 сохраняют множитель выраженности до 3; подготовленные бинарные
  факторы добавляют фиксированное число баллов при срабатывании.
- При запуске пересчитываются баллы всех профилей и ранги в отдельном временном
  кеше. Сортировка — сумма баллов по убыванию, затем стабильный ID. Подготовленные
  Parquet, исходные поля, пороги и модель IF не меняются.
- При наличии `source-assessment-v3` (или совместимого `source-assessment-v2`) загружаются все 12 факторов. L01 проверяет
  общие карты с разными сравнимыми владельцами, N01 — отличие имени при
  независимой связи, D02 — документы связанного профиля, M07 — повторную пару
  минимум в три даты и на двух направлениях. Источники и подтверждения сохранены.
- Дополнение 3.0 выполняет глобальный поиск похожих имён, показывает найденные
  пары и точные причины недоступности. Кандидаты без подтверждающего документа
  или карты показаны отдельно, без начисления баллов и объединения профилей.
  Соберите его командой `python scripts/build_source_assessment.py`, затем
  перезапустите backend. По умолчанию новый каталог выбирается автоматически.
  Если задан `YOYO_ASSESSMENT_ROOT`, он должен указывать на новый каталог.
- B01 недоступен без явных неявок; T01 — без двух подтверждённых перемещений
  с точным временем; D03 — без подтверждённого пространства имён эмитента билета.
  Причины показаны в карточке. Эти проверки не заменяются случайными значениями.
- Для зависимых подтверждений учитывается максимум баллов внутри группы,
  исключённые повторные баллы объясняются в карточке.
- Новый ZIP продукта при загрузке получает тот же снимок весов, который был
  прочитан при старте сервера. Изменение файла во время работы ничего не меняет
  до перезапуска. Демо использует тот же актуальный рейтинг.

`GET /api/metadata` → `scoring`: применённые `weights`, `config_sha256`,
`run_id`, `prepared_markers`, `pending_markers`. В `snapshot` сохранены сведения
о старом рейтинге. `evaluation` и IF относятся к исходному snapshot и не
являются новой оценкой качества после изменения весов. В карточке доступны
актуальные баллы и сохранённые исходные значения.

Конфиг `markers_v2.yaml` описывает согласованную политику и условия факторов;
для оперативной смены весов используется именно `scoring.yaml`. Если менять
условия, пороги или правила связи, потребуется новый расчёт свидетельств.

Если порт занят:

```powershell
& .\.venv\Scripts\python.exe -m yoyoflot.product.web `
  --product $product --host 127.0.0.1 --port 8502
```

Тогда адрес будет `http://127.0.0.1:8502/`.

### Проверки по доступным данным (T32)

Перед запуском сервиса подготовьте отдельное дополнение на исходном архиве,
canonical Parquet и существующем продукте:

```powershell
& .\.venv\Scripts\python.exe scripts\build_source_assessment.py
& .\.venv\Scripts\python.exe scripts\audit_source_assessment.py
```

Пути можно задать параметрами `--product`, `--canonical`, `--archive`,
`--raw-dir`, `--output`. Defaults рассчитаны на текущую структуру этого проекта.
Сборка проверяет хеши и не меняет старый продукт. Каталог результата неизменяемый:
при смене входов укажите новый `--output`.

Сервис автоматически предпочитает `source-assessment-v3` рядом с каталогом
продукта; `source-assessment-v2` и старый `source-assessment` используются как совместимый резерв.
Подключается только дополнение именно этого snapshot. Для другого расположения:

```powershell
$env:YOYO_ASSESSMENT_ROOT = (Resolve-Path .\artifacts\source-assessment-v3).Path
```

Явно заданное дополнение с неправильным хешем или неполными файлами вызывает
ошибку. При отсутствии дополнения доступен исходный рейтинг, а исходные
документы показываются как недоступные: поиск чужого паспорта по имени удалён.
`YOYO_CANONICAL_ROOT` больше не используется для чтения документов в вебе.
После обновления Python-кода или подключения дополнения перезапустите сервер.

В интерфейсе охват, срабатывания и установленная идентичность — отдельные
счётчики. Исходный snapshot не меняется; рабочий рейтинг пересчитывается по
проверенным результатам и `scoring.yaml`. В карточке все 12 маркеров находятся
в одном блоке. Под сводными счётчиками раскрывается таблица результатов
по каждому фактору: сколько проверено, сколько совпадений, скольким начислены баллы.
Для N01 отдельно показаны профили с похожими именами без подтверждающего
идентификатора. В карточке можно раскрыть сами написания и найденные пары,
затем перейти к другому профилю. Такие кандидаты не добавляют баллы.
Нажатие на положительное число совпадений открывает пример профиля с этим
маркером, включая профили за пределами топ-50/100/1000.
`GET /api/users` принимает `eligibility=assessed|not_assessed|identity_accepted|identity_ambiguous`
и прежние статусы; `GET /api/profile` возвращает отдельные `additional_factors`.

## 4. Запуск на Linux/macOS

```bash
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -e .
python -m yoyoflot.product.web --product /absolute/path/to/source-product
```

Для доступа к серверу из локальной сети можно указать:

```bash
python -m yoyoflot.product.web \
  --product /absolute/path/to/source-product \
  --host 0.0.0.0 --port 8501
```

## 5. Demo-режим

Кнопка **Открыть demo-шпионов** выбирает первые пять профилей из реального
рейтинга активного snapshot. Новые люди, перелёты и метки не создаются. Это
демонстрационное подмножество реального датасета, а не утверждение, что выбранные
люди доказанно являются шпионами.

Можно запустить сразу в demo-режиме:

```powershell
& .\.venv\Scripts\python.exe -m yoyoflot.product.web `
  --product $product --demo
```

Кнопка **Вернуть основной набор** возвращает полный snapshot.

## 6. Загрузка другого продукта

1. Соберите или получите ZIP уже готового product snapshot.
2. Запустите веб-сервис на любом исходном snapshot.
3. В интерфейсе нажмите **Загрузить snapshot**.
4. Выберите ZIP.

Сервер проверит `run_manifest.json`, контрольные суммы, обязательные таблицы,
пути внутри архива и лимиты размера. Raw-архив преподавателя и произвольные
файлы для выполнения через эту кнопку не принимаются.

## 7. Docker

Нужен Docker Desktop с включённым Compose. Путь к product snapshot задаётся
через переменную `YOYO_PRODUCT_PATH`:

```powershell
cd C:\Users\dv-te\Desktop\DS\yoyoflot
$env:YOYO_PRODUCT_PATH = (Resolve-Path .\artifacts\source-product).Path
docker compose up --build
```

Откройте `http://localhost:8501/`. Остановить контейнер:

```powershell
docker compose down
```

В Linux/macOS:

```bash
YOYO_PRODUCT_PATH=/absolute/path/to/source-product docker compose up --build
```

Snapshot монтируется в контейнер только для чтения. Docker упаковывает веб-сервис
и окружение; он не запускает полный raw-конвейер по кнопке загрузки.

Compose монтирует `artifacts/source-assessment-v3`, `artifacts/source-assessment-v2`
и совместимый старый `artifacts/source-assessment` только для чтения. Другие пути задаются через
`YOYO_ASSESSMENT_V3_PATH`, `YOYO_ASSESSMENT_V2_PATH` и `YOYO_ASSESSMENT_PATH`; дополнение должно быть
собрано для подключённого `YOYO_PRODUCT_PATH`. Без манифеста дополнения
контейнер показывает только исходные проверки.

`configs/scoring.yaml` также смонтирован для чтения; путь можно изменить через
`YOYO_SCORING_PATH`. После редактирования весов выполните
`docker compose restart yoyoflot`, затем обновите страницу. Если изменился сам путь монтирования,
выполните `docker compose up -d --force-recreate yoyoflot`. Пересобирать образ
при изменении весов в смонтированном конфиге не нужно.

## 8. API для проверки

При работающем сервере можно проверить API из PowerShell:

```powershell
Invoke-RestMethod http://127.0.0.1:8501/api/metadata
Invoke-RestMethod 'http://127.0.0.1:8501/api/top?limit=100'
Invoke-RestMethod 'http://127.0.0.1:8501/api/users?limit=20&offset=0&sort=rank'
Invoke-RestMethod 'http://127.0.0.1:8501/api/profile?id=PERSON_ID'
```

Основные маршруты:

- `GET /api/metadata` — окно наблюдений, размеры, режим и ограничения;
- `GET /api/top?limit=50|100|1000` — рейтинг;
- `GET /api/users?limit=&offset=&q=&eligibility=&sort=` — вся популяция;
- `GET /api/profile?id=...` — факторы, evidence, маршруты и IF;
- `GET /api/marker-related?id=...&marker=N01&offset=0&limit=10` — найденные пары имён с основаниями сравнения и страницами;
- `POST /api/upload` — ZIP проверенного snapshot через multipart/form-data;
- `POST /api/demo` и `POST /api/reset` — переключение demo-подмножества.

## 9. Типовые ошибки

| Сообщение | Что проверить |
|---|---|
| `--product is required` | Передан ли параметр `--product` и существует ли каталог |
| `Not a completed supported product` | Есть ли полный `run_manifest.json` и совпадают ли контрольные суммы |
| `ZIP не является проверенным продуктом` | Архив должен содержать готовый snapshot, а не raw-файлы |
| `Address already in use` | Запустите с другим `--port`, например `8502` |
| Demo не включается | Demo строится из активного source snapshot; сначала укажите корректный `--product` |
