# Контракт продукта 2.0 · source_dataset

Полная сборка принимает исходный архив преподавателя и проверяет его SHA-256.
Ядро публикует профили, сегменты и полные `person_links` / `segment_links`.
Промежуточный продукт содержит три базовых фактора. Оценка исходников версии
`source-assessment:4.0` добавляет подготовленные проверки, используя все
подтверждённые связи. `product/compile.py` публикует итоговый снимок.

`run_manifest.json` содержит schema_version=2.0, status=complete,
data_mode=source_dataset, product_kind=published_scoring, run_id, версии входов,
контрольные суммы, количества и ограничения. Неизвестные или изменённые
входы отклоняются. Снимок неизменяемый; хеши обеспечивают проверку целостности,
но не доказывают истинность каждого исходного события.

| Файл | Содержание |
|---|---|
| tables/persons.parquet, tables/segments.parquet | Исходные профили и сегменты |
| tables/person_links.parquet, tables/segment_links.parquet | Все проверенные связи с исходными записями |
| tables/features.parquet | Базовые числовые признаки |
| tables/explanations.parquet | Подготовленные факторы, статусы, вклады и свидетельства |
| tables/rankings.parquet, tables/top50.parquet | Итоговый рейтинг по баллу и его первые 50 строк |
| baseline_explanations.parquet, baseline_rankings.parquet | Сохранённая база для числовой проверки |
| scoring.yaml, scoring.json | Точные веса, версия расчёта и статистика |
| assessment/ | Проверки исходных записей и их свидетельства |
| source_observations.parquet | Исходные канонические наблюдения для полных карточек |
| airports.csv, reference_manifest.json | Проверенный справочник координат |
| provenance/, base_manifest.json | Происхождение и манифест промежуточного продукта |

Модели pickle/joblib отсутствуют. Веб не пересчитывает рейтинг и принимает
только итоговые снимки. Старый продукт необходимо пересобрать. При явной
передаче весов веб проверяет совпадение с опубликованной конфигурацией.

API сохраняет GET /api/metadata, /api/top, /api/users, /api/profile,
/api/profile/source и /api/marker-related; точные параметры см. `product/web.py`.
POST /api/upload принимает ZIP готового снимка, /api/demo включает ограниченный
просмотр существующих профилей, /api/reset возвращает полный просмотр.
Это состояние отдельно для каждого браузера. Генерации демонстрационных
пассажиров и выполнения кода из ZIP нет. Неизвестный ID — 404,
ошибочные параметры — 400. При сетевом размещении требуется токен доступа.

Карта сохраняет все сегменты, в том числе без координат. Неизвестный аэропорт
не заменяется предполагаемой точкой. Выгрузка и сайт читают одинаковые таблицы.
