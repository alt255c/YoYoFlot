# Планируемый контракт интерфейса — 17.10.2026

Статус: **проект контракта для T17–T24**, не существующий API или схема Parquet.
Текущие таблицы T11–T15 и их схемы этим документом не изменяются.
Обязательны [требования](requirements.md) и [каталог критериев](markers.md).

## Режим и версия

Каждый будущий продукт содержит `schema_version`, `run_id`, `data_mode`,
`status`, окно наблюдения, версии конфигураций и контрольные суммы входов.
Допустимые режимы: `synthetic_demo` и `aggregate_real`. Только завершённый,
проверенный снимок разрешается читать. Неизвестная версия, незавершённый статус
или смешение `run_id` блокируют загрузку.

`synthetic_demo` содержит исключительно независимо сгенерированные вымышленные
профили и события. В манифесте сохраняются версия генератора, seed и декларация
происхождения. Маркировки недостаточно: проверяются разрешённый каталог входа,
его манифест и отсутствие импорта реальных персональных таблиц.
Переименование или хеширование реальных записей не допускается.

В `aggregate_real` разрешены только заранее подготовленные агрегаты и отчёт
качества. Персональные таблицы и маршруты не входят в публикуемый снимок.
Параметры подавления малых групп и укрупнения времени/географии обязательны
в метаданных; неподготовленные агрегаты не публикуются.

## Рейтинг учебных профилей

Единица строки: `(run_id, profile_id, window_start, window_end, ranking_mode)`.
Внутренний `person_id` может сохраняться в изолированном учебном расчёте для
совместимости T13–T15; внешнее поле `profile_id` никогда не указывает на реального
человека. В режиме реальных агрегатов этой таблицы нет.

| Поле | Тип / смысл |
|---|---|
| `rank` | Целое от 1; null вне допустимого рейтинга |
| `profile_id`, `display_name` | Стабильный учебный ключ и вымышленное имя/псевдоним |
| `matched_criteria_count` | Число различных сработавших независимых групп |
| `available_criteria_count`, `enabled_criteria_count` | Число доступных/включённых групп; не число исходных признаков |
| `rule_score` | Дополнительный балл правил с версией формулы; не вероятность |
| `if_score`, `combined_score` | Nullable экспериментальные оценки; не влияют скрыто на основной порядок |
| `eligibility_status`, `eligibility_reason_ru` | `eligible`, `insufficient_data` или `no_matches` и русское пояснение |
| `window_start`, `window_end`, `coverage_summary_ru` | Окно и пределы покрытия |
| `summary_ru` | Краткие фактические причины высокого места |
| `ranking_mode`, `model_version`, `run_id` | Явно выбранный способ и версии результата |

Основной `ranking_mode=criteria_count`: число сработавших групп по убыванию,
затем `rule_score` по убыванию и `profile_id` по возрастанию. Техническое
разрешение равенств не трактуется как разница в необычности.
`get_top_profiles(limit=50)` возвращает максимум 50 допустимых записей с хотя
бы одним сработавшим основанием; также возвращает общее число подходящих
профилей и причину короткого списка. Фильтры не меняют метод молча.

## Результат критерия и объяснения

Единица строки: `(run_id, profile_id, criterion_id, window_start, window_end)`.

| Поля | Обязательный смысл |
|---|---|
| `criterion_id`, `group_id`, `criterion_version`, `title_ru` | Критерий, группа независимого голоса, версия и русское название |
| `status` | `matched`, `not_matched`, `unavailable`, `disabled` |
| `value`, `unit`, `operator`, `threshold` | Фактическое значение и условие; null для неприменимых элементов |
| `used_observations`, `availability_reason_ru` | Число пригодных учебных наблюдений и причина недоступности |
| `reference_id`, `reference_size`, `reference_value` | Nullable сведения о фиксированном учебном фоне |
| `contribution`, `group_contribution` | Вклад критерия и итоговый ограниченный вклад группы без удвоения |
| `explanation_ru`, `evidence_segment_ids` | Проверяемый русский текст и ссылки на учебные события |
| `config_hash`, `run_id` | Версия правила и снимка |

Порог и значения сохраняются вместе с результатом: изменение YAML после расчёта
не должно переписать прошлое объяснение. Идентификаторы подтверждений обязаны
принадлежать тому же профилю и снимку. Недоступность не получает обвинительного
текста или положительного вклада.

## Учебные маршруты

Единица строки: `(run_id, profile_id, segment_id)`. Источник — различимые
учебные сегменты, а не отдельная строка каждого исходного свидетельства.

| Поля | Смысл |
|---|---|
| `origin_airport_id`, `destination_airport_id` | Nullable ключи аэропортов из справочника данного снимка |
| `origin_name`, `destination_name`, `origin_iata`, `destination_iata` | Nullable подписи точек |
| `origin_latitude`, `origin_longitude`, `destination_latitude`, `destination_longitude` | Nullable координаты из версии справочника; не выводятся из названия страны |
| `departure_date`, `departure_local`, `departure_utc`, `departure_precision` | Сохранённые дата/время вылета и точность без додумывания часов |
| `departure_label_ru` | Дата вылета для видимой подписи или «Дата неизвестна» |
| `identity_status`, `resolution_status`, `participation_status` | Отдельные статусы уверенности и вида участия |
| `event_kinds`, `source_ids`, `evidence_refs` | Тип учебного свидетельства и путь к учебному источнику |
| `is_plottable`, `unplottable_reason_ru` | Возможность нарисовать обе точки и понятная причина ограничения |
| `run_id`, `profile_id`, `segment_id` | Ключи, исключающие смешение профилей и версий |

В существующем T13 у `segments` нет координат: будущий слой T22 присоединяет
их по `airport_id` к справочнику того же учебного снимка, с проверкой уникальности
ключей. `graph_eligible` служит допуском графа и не является фильтром всей карты.
Для учебной карты сохраняются все сегменты, включая явно помеченные неполные
и неопределённые. Неизвестная точка не создаёт произвольную стрелку.

Хронология использует известную дату/время с сохранённой точностью;
недатированные записи показываются отдельно. Без времени порядок внутри дня
не выдаётся за установленную последовательность. Направление каждой стрелки —
origin → destination; дата подписи относится к вылету. Повторные маршруты
не схлопываются до одной последней даты.

`get_profile_routes(profile_id, date_range=None)` возвращает список и баланс:
`total_segments = plottable_segments + unplottable_segments` до фильтра,
а после фильтра — ещё `visible_segments` и `hidden_by_filter`. Карточка и карта
используют один результат запроса. Вспомогательный маршрут без географии
всегда остаётся в списке; скрытие по фильтру явно показано.

## Планируемый слой доступа T22

- `get_product_metadata()` — версия, режим, окно, ограничения и качество.
- `get_top_profiles(limit=50)` — учебный топ с причинами и покрытием.
- `get_profile_dossier(profile_id)` — учебная карточка и результаты критериев.
- `get_profile_routes(profile_id, date_range=None)` — учебная карта и баланс.
- `get_aggregate_overview()` — допустимые агрегаты без индивидуального перехода.

Все операции привязаны к выбранному снимку. Операции учебного
топа/карточки/маршрутов в режиме `aggregate_real` недоступны: это проверяется
в слое доступа, а не только скрытой кнопкой. Неизвестный ключ обрабатывается
явно, запрос не подставляет предыдущий профиль.

Рейтинг готовится заранее. Интерфейс загружает только 50 строк и карточку
выбранного учебного профиля; весь набор маршрутов не отправляется в браузер.
Кэш учитывает как минимум `run_id`, `data_mode`, `profile_id`, режим рейтинга
и фильтр дат. Целевые задержки фиксируются в T22 после замера на согласованном
оборудовании; произвольные обещания времени сейчас не задаются.

## Поставка и проверка

Таблицы рейтинга, критериев и маршрутов — новые планируемые производные
артефакты. Окончательные имена файлов и физические типы утверждаются в T17/T22
вместе с изменением схем и всех потребителей; существующие выходы не
переименовываются в этой документационной поставке. Пустые результаты имеют
схему и причину. Экспорт сохраняет режим, окно, версии и ограничения.

T20/T21 проверяют принадлежность учебных событий профилям, источники данных,
детерминированность топа, объяснения, достаточность и недоступность персональных
операций для реальных данных. T23/T24 проверяют выбор всех 50 строк,
направления, видимые даты, пропуски, линию перемены дат и работу без сети.
