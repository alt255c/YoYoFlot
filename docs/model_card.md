# T19: учебный Isolation Forest

В пакете 0.11.0 добавлена [автоматическая проверка T20](evaluation.md) на
отдельном семействе holdout, с чувствительностью и абляциями. Независимое
содержательное ревью и T21 остаются незавершёнными; IF/граф не продвигаются.
Ниже сохранены метод и ограничения T19.

Пакет 0.10.0; модель `if-demo-1.0`; схемы 1.0. Ветка `reape/T19` создана
непосредственно от `reape/T18` / `4d15d72`. Основной результат T17 по числу
независимых критериев сохранён. IF и комбинация являются отдельными
экспериментами. `ui_ready=false`, приёмка — `pending_T20_review`.

## Данные и область применения

Все индивидуальные входы независимо вымышлены генератором проекта. Gate
проверяет не только флаг/хеши, но и совпадение каждой логической строки с
воспроизведённым рецептом. Реальные данные T11–T16, их обезличенные копии и
произвольно подменённые профили не принимаются.

Генератор `yoyoflot-independent-fiction-v2` добавляет разнообразие числа
поездок, интервалов, возвратов и направлений. Он создаёт не более 500 профилей
по 60 сегментов в фиксированном окне 01.01–31.03.2026. В ID включён seed;
разные seed дают непересекающиеся ID. Сценарии с недостаточным покрытием,
пустой историей, неизвестной географией или датами сохранены для проверки null.
Старый v1 и команды T17/T18 по умолчанию остаются совместимыми.

| Роль | Seed / профилей по умолчанию | Использование |
|---|---|---|
| training | 101 / 300 | Только этот набор поступает в `IsolationForest.fit` |
| calibration | 202 / 200 | Замороженные распределения IF и ключей правил |
| evaluation | 17 / 120 | Итоговые оценки и отдельные топы |

Все три seed должны различаться, множества profile_id не пересекаются.
Параметры опорных наборов задаются конфигурацией; evaluation — `--seed` и
`--profiles`. Можно передать собственные **проверяемые учебные** наборы через
`--input`, `--reference`, `--calibration`. Подписи сценариев/целевые метки в
матрицу не входят. При стандартных параметрах пригодны 180 обучающих профилей
с 136 различными float32-векторами, 120 калибровочных и 72 из 120 оценочных.

Это разделение по профилям для оценки необычности внутри одного известного
окна. Прогнозирование будущих поездок не реализовано. Одинаковое семейство
генератора во всех ролях ограничивает проверку обобщения: другие seed сами по
себе не являются независимой проверкой качества на новых типах сценариев.
Training содержит разные учебные режимы и не размечен как «чистая норма»;
его состав и доля необычных сценариев не были оптимизированы по качеству.
Они также требуют проверки чувствительности в T20.

## Контракт признаков и окна

До fit для каждой роли строятся проверенные родители T17 и, при включении,
T18. Совпадают логический SHA-256 входа, profile_id, версии модели/графа,
`data_mode`, начало окна и `as_of`. Сохраняются идентификаторы и SHA-256
родительских манифестов; разные версии не соединяются молча.

| Столбец по умолчанию | Смысл | Доступность |
|---|---|---|
| `trip_rate_30_days` | Число датированных сегментов / покрытые дни × 30 | Правила покрытия и минимального числа наблюдений T17 |
| `quick_return_share` | Доля быстрых обратных соседних пар среди допустимых пар | Известные даты/маршруты и знаменатель T17 |
| `repeated_route_share` | Доля повторов направленного маршрута T17 | Известная география и достаточное число сегментов |

Формулы и знаменатели полностью определены в [T17](t17_rules.md#критерии-и-доступность).
Порядок столбцов фиксирован конфигурацией и сохраняется в модели и каждой
строке `matrices.parquet`. Числа приводятся к float32, как при fit и повторном
score. Масштабирование и обучаемое предобрабатывание не выполняются.

Идентификаторы, имена, конкретные страны, качество/полнота источника, число
доступных признаков и `total_segments` не являются модельными признаками.
Доступность — отдельная маска. Все выбранные признаки должны быть известны,
а правила P0 — сопоставимы (`eligible` или `no_matches`). Пропущенные значения
не заменяются нулями/средним; профиль получает `insufficient_data`, null-оценку
и русскую причину. Настоящий известный ноль сохраняется числом. Такая политика
выбирает только полные профили и может смещать состав оцениваемой группы.

Даты позже `as_of` не участвуют в численных признаках; окно правил обрезается
той же датой. При включении графа `as_of` в обоих конфигах должен совпасть.
Полная исходная история остаётся в `parents/*/rules/input`; будущая карта не
должна терять сегменты вследствие фильтра для модели. Неизвестные даты не
превращаются в даты внутри окна.

## Обучение и балл

Конфигурация — `configs/isolation_forest.yaml`. Она отделена от строгого
формата правил `configs/model.yaml`; старые команды не начинают обучать ML.

| Параметр | По умолчанию |
|---|---:|
| `n_estimators` | 200 |
| `max_samples` | min(128, число пригодных training) |
| `random_state` | 1901 |
| `n_jobs` | 1 |
| `max_features` | 1.0 |
| `bootstrap` / `warm_start` | false / false |
| `contamination` | auto |
| Минимум полных training / calibration | 32 / 24 |
| Минимум различных training-векторов после float32 | 4 |

Перед fit строки сортируются по profile_id. sklearn импортируется для fit
после проверок достаточности; выключенный эксперимент/малый/вырожденный
опорный набор не создаёт модель. Основной результат правил всё равно сохранён.

`if_score = -IsolationForest.score_samples(X)`: больший балл означает более
необычное сочетание признаков относительно обученного леса. Порог `predict`,
бинарные классы и вероятность какого-либо свойства человека не выдаются.
`contamination=auto` фиксирует параметр библиотеки; его offset не используется
в ранжировании. Эти свойства API описаны в
[официальной документации sklearn](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html).

## Калибровка и три независимых выхода

Для каждого значения x используется только замороженная калибровочная выборка C:

`percentile(x) = (число C < x + 0.5 × число C = x) / len(C)`.

Равные значения имеют одинаковый midrank. Значения вне опорного диапазона
получают 0 или 1. IF-калибровка использует сырые `if_score`; калибровка правил
использует лексикографический ключ `(matched_criteria_count, rule_score)`.
Это сохраняет приоритет числа критериев и допускает разные веса правил.
Процентили вычисляются на одном пригодном calibration-наборе, не на текущей
оценочной пачке. Изменение evaluation не меняет модель или оба распределения.

| Выход | Порядок |
|---|---|
| Основной `rankings.parquet`, `top50.parquet` | Число критериев ↓, балл правил ↓, profile_id ↑; точная копия T17 |
| `if_rankings.parquet`, `if_top50.parquet` | Сырой IF ↓, profile_id ↑ |
| `combined_rankings.parquet`, `combined_top50.parquet` | `0.5 × rule_percentile + 0.5 × if_percentile` ↓, profile_id ↑ |

В экспериментальном топе — максимум 50 строк со статусом `scored`, включая
допустимые профили без срабатывания правил. Остальные остаются в полном файле
с `rank=null`. При недоступности одной части комбинация тоже null; вес второй
части не увеличивается автоматически. Веса проверяются как конечные числа
от 0 до 1 с суммой 1. Это гипотеза T20, а не установленная лучшая комбинация.
IF не становится дополнительным сработавшим критерием.

Русское поле `explanation_ru` эксперимента объясняет направление балла и
калибровку. Оно не является разложением решения дерева по признакам и не
выдаёт причины правил за объяснение IF. Подробные причины правил с числом,
порогом и evidence сохранены в `parents/evaluation/rules/model_explanations.parquet`.
Jaccard пересечения топов в отчёте описывает согласие методов, не точность.

## Граф

`include_graph=false` по умолчанию: T18 не рассчитывается, его конфиг не
требуется. Для отдельного опыта явно включается `include_graph=true`:
добавляются `excess_repeated_companions` и `max_positive_pair_excess_days` из
T18. Знак первого признака сохранён; p-value и количество ошибок не подаются
в IF. Оба показателя должны быть доступны; ноль допустим, неизвестное — null.
Проверяются совпадение входа/окна и `m07_status=disabled`.

M07 остаётся выключенным, граф не добавляет голос в основном рейтинге. Для
графовых величин важны размер/покрытие наблюдаемой группы и условный фон.
Различие размеров training/calibration/evaluation может менять их масштаб;
стандартное включение графа и вывод об улучшении качества ожидают T20.

## Артефакты и связи

Авторитетные схемы — `models/if_artifact.py`. Все новые таблицы имеют metadata
`schema_version=1.0`, `data_mode=synthetic_demo`, `run_id` T19.

| Файл | Ключ / содержимое |
|---|---|
| `matrices.parquet` | `(role, profile_id)`; dataset SHA, имена, `values: list<float32>`, маски, eligible, причина, окно |
| `reference_scores.parquet` | `(role, profile_id)`; оценки всех training/calibration, включая недоступные |
| `if_*`, `combined_*` | profile_id; nullable rank/оценки, статус, счётчик/балл правил, текст метода и окно |
| `rankings.parquet`, `top50.parquet` | Байтовая копия основного evaluation-результата T17, с его run_id |
| `model.joblib` | Лес, параметры, порядок признаков, окно, calibration-распределения и runtime; отсутствует, если fit не выполнен |
| `parents/<role>/rules`, `parents/<role>/graph` | Полные снимки родителей; graph только при явном включении |
| `config/isolation_forest.yaml` | Точные исходные байты конфига; правила/граф также заморожены у родителей |
| `model_metadata.json` | Входы, параметры, версии, код, ссылки на родителей, формулы и ограничения |
| `report.json`, `summary.txt` | Счётчики, доступность fit/оценок, время, согласие топов, статус приёмки |
| `run_manifest.json` | Полный состав файлов, SHA-256, запрос и стабильный run_id |

Основной T17 run_id указан в `model_metadata.primary_parent`; соединение
с экспериментом выполняется по profile_id **внутри evaluation одного T19-снимка**.
Нельзя требовать равенства run_id скопированных основных и экспериментальных
таблиц. Родители разных ролей не смешиваются. `reference_scores` для training
является диагностикой обучающей выборки, не независимой оценкой качества.

Снимок публикуется атомарно из собственного временного каталога под OS-lock.
При прерывании он не появляется как завершённый; готовые родители пригодны
для повторного запуска. Существующий повреждённый/несовместимый выход не
перезаписывается. При кэш-попадании проверяется полный состав и SHA-256 без
загрузки pickle. Смена кода, параметров, родителей или библиотек меняет run_id.

## Сохранение модели и воспроизводимость

Модель сохраняется в joblib и **сразу** читается из только что созданного
собственного временного файла; оценки calibration должны совпасть точно.
Нет команды импорта произвольного `model.joblib`. Joblib использует pickle,
поэтому чужой файл может исполнить код; SHA-256 обеспечивает целостность
снимка, а не удостоверяет доверенное происхождение файла.
[Ограничения формата](https://scikit-learn.org/stable/model_persistence.html).

Записываются Python, sklearn, numpy, scipy, joblib, PyArrow, YAML и хеш
исполняемого кода. Проверенное окружение Python 3.12 берётся из `uv.lock`:
sklearn 1.9.1, numpy 2.5.4, scipy 1.18.1, joblib 1.6.0. Загрузку между другими
версиями sklearn/окружениями не обещаем. Не меняйте зависимости после fit
для чтения этого файла. Порядок входных строк не меняет обучение; изменение
evaluation при тех же родителях training/calibration сохраняет бинарный хеш
модели в проверенном окружении. Абсолютные пути в родительских summary могут
менять хеши снимков при переносе рабочего каталога, не математические оценки.

Отделение fit от evaluation соответствует
[рекомендациям sklearn против утечки](https://scikit-learn.org/stable/common_pitfalls.html).
В [протоколе](validation/t19_validation.json) отражены проверки матриц,
reload, процентилей и основных файлов по сохранённым таблицам. Сценарный тест
направления балла подтверждает реализацию; он не измеряет качество на новых
данных. T20 должен независимо проверить сценарии, чувствительность, вклад
графа и расхождения топов. Интерфейс и его приёмка в T19 не реализуются.
