# Исправление памяти T13 — 0.6.1, 17.10.2026

Причина: лимит DuckDB 512MB оказался недостаточным для исходных крупных SQL-запросов
подготовки. Код объединял тяжёлые операции в одном запросе и собирал глобальные
состояния агрегатов списков. Сортировки могут выгружаться на диск; эти агрегаты —
нет. Точная строка запроса из короткого пользовательского лога не определяется.

Изменения:

- Документы и происхождение идентификаторов собираются по nid, по 16 384 групп.
  Идентификаторы предварительно упорядочены, ссылки и DISTINCT не меняются.
- Соединение идентификаторов и их сортировка выполняются отдельными запросами;
  соединение свидетельств пар также отделено от оконной нумерации и сортировки.
- Свидетельства пар и сегменты упорядочиваются по числовому dense_rank группы,
  затем агрегируются теми же порциями. Группа никогда не делится между порциями.
- Два DOB-свидетельства выбираются через row_number/min вместо списка.
- Лимит по умолчанию 1GB, один поток DuckDB; настройки T12 не менялись.
- Добавлены отдельные этапы прогресса, регрессия совпадения всех выходных строк,
  воспроизводитель прежнего OOM и тест нового blocking на реальном числе
  искусственных наблюдений/идентификаторов в отдельных процессах.

Проверки сохранены в docs/validation/t13_memory_*. Полных реальных Parquet в
среде нет. Измерения подготовки не являются замером всего T13 или точности ER.
Выходы T11/T12 сохраняются. Неудачный T13 запускается с начала:

```powershell
python scripts/run_t13.py --require-all
```

Если T13 уже закоммичен:

```powershell

git add -- src/yoyoflot/cli.py src/yoyoflot/__init__.py pyproject.toml tests/test_matching.py scripts/benchmark_t13_memory.py
git add -- README.md docs/matching.md docs/implementation_status.md docs/ledger/t13_memory_fix.md "docs/validation/t13_memory_*"
git commit -m "fix: bound T13 aggregation memory for full datasets"
```

data/processed, data/review, временные БД, benchmark и wheel не коммитятся.
