# T18: граф совместных учебных событий

В пакете 0.10.0 добавлен [отдельный опыт T19](model_card.md): он проверяет
описанные ниже совместимость входов/окон и политику матрицы перед fit.
Граф по умолчанию выключен, M07 остаётся выключенным. Сам T18 по-прежнему
не обучает ML. Ниже сохранена методология и статус приёмки графа T18.

Пакет 0.9.0; схема 1.0; формула `graph-demo-1.0`, фон
`daily-route-partition-1.0`. Ветка `reape/T18` создана непосредственно от
`reape/T17` / `8dc05c593529b7a83709b260e7d684f931554616`: нужны проверка
происхождения T17 и те же вымышленные профили/истории.

Это отдельный учебный граф независимо вымышленных событий. Реальные персональные
таблицы T11–T16, реальные связи, а также обезличенные/переименованные реальные
записи не принимаются. Обучения ML в T18 нет. Рейтинг T17 не меняется, M07
остаётся `disabled` до T20 и независимого ревью.

## Запуск и вход

```powershell
python scripts/run_t18.py
```

По умолчанию повторно используется независимый генератор T17: seed 17,
120 профилей. Исходные учебные таблицы находятся в `data/work/t18/demo-<hash>/`,
результат — в `artifacts/t18/graph-<hash>/`. T11–T17 пересчитывать не требуется.
PyCharm Run работает с другой рабочей папкой; `-q` оставляет итог в файле.

Для уже созданного учебного входа или замороженного входа T17:

```powershell
python scripts/run_t18.py --input data/work/t17/demo-<hash>
python scripts/run_t18.py --input artifacts/t17/rules-<hash>/input
python -m yoyoflot graph --demo --config configs/graph.yaml
```

`--seed` и `--profiles` относятся к генерации базового набора при `--demo`,
допустимы те же границы 0–500 профилей и 32-битный неотрицательный seed, что в
T17. `--config` выбирает строгий YAML графа; `--output` — новый каталог снимка,
`--artifacts-dir` — родителя автоматических имён, `--demo-dir` — базовый набор.
Прямой CLI без `--demo`/`--input` возвращает код 2; скрипт сам выбирает `--demo`.
`--help` не создаёт данные.

Внешний вход проходит `validate_demo`: проверка версии/рецепта, схем,
ограничений размера, SHA-256 и повторное получение **всех** строк независимым
генератором. Новые файловые хеши и метка `synthetic_demo` не разрешают импорт
реальных строк. Готовые произвольные графовые наблюдения снаружи не читаются.

`graph_demo.py` детерминированно добавляет к этим же сегментам явно вымышленные
экземпляры рейсов и свидетельства: посадочная запись, дубли другого источника,
подтверждённый учебный codeshare и отдельно неподтверждённые записи. Исходные
даты и маршруты T17 не меняются. Рецепт, seed 29, контрольная повторная пара и
контрольный многолюдный рейс сохраняются в метаданных. Эти служебные сценарии
не являются признаками, разметкой эффективности или допустимыми входами ML.

## Событие, допустимость и происхождение

Дата и направление сами по себе **не означают один рейс**. Нужны явные
`service_id` экземпляра события и полный номер рейса. Даже при совпадении
даты/направления/номера разные экземпляры не склеиваются. Для codeshare
необходимо прямое правило с обоими экземплярами, номерами, датой, направлением
и основанием; цепочки, циклы и неоднозначные aliases отклоняются.

Участие допускается, когда идентичность однозначна, связь разрешена, есть
`fictional_boarding_record` с `participation_status=recorded`, известны дата
и обе точки, присутствует provenance. Расписание, бронь, неопределённое участие
и спорная связь не создают ребро. Конфликт метаданных одного экземпляра либо
две противоречивые уверенные версии одного сегмента исключают все затронутые
свидетельства; порядок строк не выбирает победителя. Ошибки внешних ключей и
противоречивые дубли одного observation ID являются блокерами всего запуска.

Дубли точного observation ID учитываются один раз. Разные источники,
подтверждённые aliases и даже несколько segment ID одного профиля/события
сохраняются как evidence, но дают **одно участие**. Нельзя получить две встречи
из двух копий билета.

ID свидетельства зависит от версии генератора, seed, исходного сегмента и
назначенного экземпляра/номера рейса. Если содержание или версия учебного
события изменились, старый observation ID не используется для новой записи.
При неизменных данных и перестановке строк идентификаторы сохраняются.

Допустимость профиля требует известных покрытых дней ≥60, покрытия источника
≥0,8 и доли пригодных сегментов ≥0,8. Эти настройки демонстрационные.
Знаменатель доли включает сегменты в окне и недатированные сегменты;
известные даты вне окна исключаются. `candidate_segments` показывает пригодные
сегменты до общей проверки профиля; `eligible_segments` — после неё.
Профили с недостаточными данными не участвуют в графе/фоне, их числовые
графовые признаки равны `null`, причина сохранена. Полностью известная одиночная
история может иметь корректные нулевые числа спутников.

`as_of` в конфиге задаёт правую границу окна, по умолчанию 31.03.2026.
Будущие события не меняют поддержку, популярность рейсов, набор участников,
семейство проверок и признаки прошлого. Это проверено сравнением с обрезанным
входом. Полная исходная учебная история сохраняется в снимке: `graph_eligible`
не является общим фильтром будущей карты T24.

Цепочка проверки: ребро → `event_ids` → событие и membership профиля →
`observation_ids` → сохранённые исходные учебные наблюдения → `segment_id` T17.
Одиночные события тоже сохраняются: они нужны для правильного случайного фона.

## Повторность и условный фон

Ребро неориентированное, `profile_a < profile_b`. Сохраняются число событий,
точные ID и даты. Повторность — минимум два **различных дня** по умолчанию.
Два рейса в один день остаются двумя событиями и одним днём встречи.
Повторность сама по себе не означает необычность или личную связь.

Фон условен на `(дата, origin, destination)`. В каждой такой группе сохраняются
точный состав активных профилей и наблюдаемое число участников каждого рейса.
Участники равномерно перемешиваются между фиксированными местами. Таким образом,
сохраняются активные дни/направления каждого профиля и наблюдаемая популярность
каждого рейса. Это численность допустимых записей, а не вместимость самолёта.

Модель требует максимум одно участие профиля в группе дата/направление.
Если есть несколько разных рейсов того же профиля в одной такой группе,
запуск явно останавливается: нужен другой условный фон. Он не делает вид,
что независимая перестановка сохраняет многократные участия. Разные направления
в один день допустимы и объединяются на уровне числа дней.

Для группы с N участниками и размерами рейсов n_f вероятность совместного
события конкретной пары равна:

`p = sum(n_f * (n_f - 1)) / (N * (N - 1))`.

N≤1 даёт p=0. Пара рассматривается только в группах, где оба профиля активны.
Если в день есть несколько общих направлений, вероятность хотя бы одной встречи
равна `q_day = 1 - product(1 - p_group)`. Разные группы/дни переставляются
независимо. Сумма q_day даёт `expected_days`; распределение суммы бернуллиевских
индикаторов даёт точный **условный** верхний хвост `P(days >= observed)`.

Для редких хвостов используется логарифмическое динамическое программирование.
Если экспонента не представима как положительное float, `p_exact=null`, но
конечный `log_p_exact` сохранён: округление не выдаётся за точный ноль.
Bonferroni применяется к полному семейству всех пар допустимых профилей
`m=N_profiles*(N_profiles-1)/2`, включая ненаблюдавшиеся рёбра с p=1.
Сохраняются и скорректированное значение, и его логарифм.

Дополнительная диагностика — 199 перестановок с seed 1801. Seed каждой группы
выводится из её ключа и номера повторения, поэтому порядок строк/групп не влияет
на результат. Сохраняются среднее, его стандартная ошибка и
`mc_p_plus_one=(tail_count+1)/(B+1)`. Перестановочная оценка не заменяет точный
хвост и не объявляется независимой оценкой эффективности.

| Контрольный пример | Проверяемый результат |
|---|---|
| Один рейс и его копии | Один день, повторности нет |
| Два рейса одной пары в один день | Два события, один день, повторности нет |
| Вся группа летит одним рейсом три дня | Наблюдается 3 дня, ожидается 3, превышение 0, p=1 |
| Четыре профиля, два рейса по два места, три дня; одна пара всегда вместе | p совместного дня 1/3, ожидается 1 день, наблюдается 3, точный хвост 1/27, Bonferroni 6/27 |
| В каждом из трёх дней новые пары из четырёх профилей | Повторных спутников 0; ожидается 7/9; отрицательное превышение сохраняется |

Формула вероятности выведена подсчётом мест и проверена полным перебором
маленьких наборов; хвост сверяется с независимым перебором исходов на рациональных
числах. Для соглашения «+1» использована
[документация SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.permutation_test.html),
для коррекции — [исходник statsmodels](https://www.statsmodels.org/stable/_modules/statsmodels/stats/multitest.html).
Эти библиотеки не вызываются расчётом T18 и не добавлены как новые зависимости.

## Выходы и будущая модель

| Файл | Ключ / смысл |
|---|---|
| `graph_events.parquet` | event_id; дата, направление, экземпляр/номер, участники, сегменты и evidence |
| `graph_memberships.parquet` | event_id + profile_id; одно участие со всеми segment/observation ID |
| `graph_links.parquet` | observation_id; допустимость, причина исключения, nullable event_id |
| `coflight_edges.parquet` | profile_a + profile_b; наблюдаемые дни/события, evidence, точный и перестановочный фон |
| `graph_features.parquet` | profile_id; покрытие, доступность и агрегаты группы coflight, M07 disabled |
| `input/` | Весь базовый T17, сгенерированные graph_observations/codeshare_rules и два манифеста |
| `config/graph.yaml` | Точные байты эффективной конфигурации |
| `model_metadata.json` | Рецепты, параметры, окно, версии кода/окружения, ограничения |
| `run_manifest.json`, `report.json`, `summary.txt` | SHA-256 файлов, количества, время и русский итог |

У всех выходных таблиц есть `run_id`, `data_mode=synthetic_demo`, `graph_version`
и окно. Авторитетные типы — `features/graph.py`. Пустые таблицы сохраняют схему.

Графовые агрегаты: число спутников, число повторных спутников, наблюдаемая и
ожидаемая суммы дней по всем партнёрам, ожидаемое число повторных спутников,
знаковое превышение повторных спутников и максимальное **положительное**
превышение дней отдельной пары (`max_positive_pair_excess_days`). Ожидания
суммируются по всем возможным парам общего фона, включая нулевые наблюдения;
выбор только наблюдавшихся рёбер дал бы смещение. Максимум — описательная
статистика, не скорректированная вероятность. Все эти показатели относятся
к одной коррелирующей группе coflight и не дают отдельных голосов.

Для T19 необходимо проверить общий `input_logical_sha256`, profile ID и точное
окно T17/T18; сохранить ссылки на оба родительских снимка. Матрица признаков
должна задаваться явным списком и порядком столбцов, учитывать availability и
иметь отдельную политику пропусков. ID, имена, названия сценариев/пары генератора,
source/coverage и p-value не становятся автоматически числовыми признаками.
Политику обучения/оценки, разделение учебных сценариев и чувствительность к
настройкам ещё предстоит определить в T19/T20. Подготовка графа не означает
правильность будущего обучения и не включает его скрыто.

Условный фон не учитывает все возможные обычные причины встреч: рабочие группы,
семейные поездки и расписания. Его вероятности не являются вероятностью
принадлежности или характеристикой реального человека. M07/порог, качество
опорного набора и выводы требуют T20; сейчас альфа-порог и автоматический
положительный голос отсутствуют. `training_performed=false`, `ui_ready=false`,
`acceptance=pending_T20_review`.

Снимки атомарны, независимы от рабочих файлов, проверяются при повторе и не
перезаписываются. Ошибка/прерывание удаляют незавершённый снимок. Лимиты размера
события, числа пар и перестановочной работы проверяются до разворачивания пар;
превышение вызывает ошибку без усечения рейса или молчаливого урезания выборки.
Коммитятся код, конфиги, тесты и протокол; сами снимки/данные игнорируются Git.

Дополнительно согласованы `uv.lock`, версия пакета и экспорт requirements:
в lock добавлена уже требуемая `tzdata==2026.5`. Остальные закреплённые версии
не изменены. Проверки: [протокол T18](validation/t18_validation.json).
