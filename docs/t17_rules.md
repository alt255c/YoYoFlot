# T17: учебные правила и топ-50

Версия пакета 0.8.0, модель `rules-demo-1.0`, схемы учебных таблиц 1.0.
Ветка `reape/T17` создана **непосредственно от `reape/T16`**:
`0f3c311448db83ae5e9251f2431d866bc44c3530`. Переноса коммитов T16 через
`develop` не было. Код ядра данных T16 сохранён.

## Запуск

В существующем виртуальном окружении из корня проекта:

```powershell
python scripts/run_t17.py
```

Скрипт работает и через PyCharm Run с другой рабочей папкой. Он независимо
создаёт 120 вымышленных профилей с seed 17 и рассчитывает правила. T11–T16
повторять не требуется; `data/processed` не читается и не изменяется.
Результат сохраняется в `artifacts/t17/rules-<fingerprint>/`, исходный учебный
набор — в `data/work/t17/demo-<fingerprint>/`. Повторная команда проверяет
контрольные суммы и возвращает уже завершённый снимок.

Другие параметры и явный CLI:

```powershell
python scripts/run_t17.py --seed 42 --profiles 120
python -m yoyoflot train --demo --config configs/model.yaml
python scripts/run_t17.py --input data/work/t17/demo-<fingerprint>
python scripts/run_t17.py -q
```

`--profiles` допускает 0–500, seed — целое от 0 до `2**32-1`.
`--input` принимает только ранее созданный этим независимым генератором набор.
`--output` задаёт новый каталог снимка, `--artifacts-dir` меняет родительский
каталог автоматических имён, `--demo-dir` меняет каталог генератора.
`-q` сохраняет итог в `summary.txt`, не печатая его в терминал. `--help` ничего
не создаёт. `python -m yoyoflot train` без выбора входа возвращает код 2.

Входы T15 (`person_id`, реальные `features.parquet` и `feature_coverage.parquet`)
и снимки T16 **не являются входами этого учебного рейтинга**. Обезличивание,
хеширование ID или добавление `synthetic_demo` к реальным записям не подходит.
Реальные сведения могут использоваться отдельно для агрегированной статистики;
такой расчёт не входит в T17.

## Происхождение и воспроизведение набора

`models/demo.py` не читает исходники, T15 или T16. Он строит собственные ID,
подписи «Учебный профиль N», даты и маршруты из фиксированного рецепта.
Коды аэропортов — общедоступные обозначения; сами поездки полностью придуманы.
Окно 01.01–31.03.2026 включает 90 покрытых дней и не выводится из активных месяцев.
Десять сценариев включают обычную активность, отдельные и совместные срабатывания,
пустую историю, неполное покрытие, неизвестные даты и аэропорты. Это проверки
арифметики, а не обучающие метки или независимая оценка эффективности.

`demo_manifest.json` содержит режим, происхождение, версию генератора, seed,
размер, окно, логический SHA-256 и SHA-256 двух Parquet. Перед расчётом проверяются
схемы, размеры и хеши; затем генератор повторяется и **каждая логическая строка**
сравнивается с ожидаемой. Одной метки режима и даже новых файловых хешей мало.
Перестановка физических строк допускается: сравнение проводится по стабильным ID.

Снимок сохраняет заново сгенерированные канонические входы, точные байты YAML,
версию пакета/Python/PyArrow/PyYAML и хеш исходников модулей модели. `run_id`
зависит от логического входа, нормализованной конфигурации и этого окружения.
Другой seed, порог, код или окружение создают другую версию. Комментарий в YAML
не меняет смысл конфигурации; при повторном использовании остаётся исходный
замороженный конфиг снимка.

Снимок публикуется целиком через временный каталог под OS-блокировкой.
Готовый выход не перезаписывается, ошибки и Ctrl+C не оставляют частичный снимок.
Повреждённый существующий снимок вызывает ошибку: его нельзя незаметно заменить
другим результатом. Учебный вход и выход не должны пересекаться.

## Критерии и доступность

Все условия — `value >= threshold`. Числа в конфиге **демонстрационные и
не проверены T20**. Имена, документы, национальность, политические сведения
и посещение конкретной страны не используются.

| ID / независимая группа | Формула в покрытом окне | Порог по умолчанию | Минимальная поддержка |
|---|---|---|---|
| M01 / activity | `dated_segments * 30 / covered_days` | 6 перелётов / 30 дней | 6 датированных сегментов |
| M02 / quick_return | Число быстрых обратных пар / число сопоставимых соседних пар | 0,2 | 3 сопоставимые пары |
| M03 / repetition | `1 - unique_known_routes / known_route_segments` | 0,8 | 6 сегментов с обоими аэропортами |

Маршрут направленный: A→B и B→A различаются. Сегмент считается один раз по ID;
противоречивые дубли отклоняются. Неизвестные даты не подменяются полуночью.
В M02 рассматриваются **соседние** события по известным датам: A→B, затем B→A
с разницей 1–2 дня. Несколько событий в один день без времени не упорядочиваются
по ID: затронутые пары исключаются. Неизвестные аэропорты разрывают сравнение;
неизвестная дата делает M02 недоступным, поскольку соседство восстановить нельзя.
Остальные однозначные соседние пары входят в знаменатель, даже если возврата нет.

Общие условия доступности: однозначный профиль, покрытие источника ≥0,8,
известное окно ≥60 дней, доля известных дат ≥0,8. В доле дат участвуют события
в окне и недатированные события; датированные события вне окна исключаются.
M02 дополнительно требует ≥0,8 сопоставимых пар среди соседних; M03 — ≥0,8
сегментов с обоими аэропортами среди датированных в окне. Поддержка каждого
критерия проверяется отдельно. Отсутствие данных даёт `null` и причину,
а не нулевой признак и не положительный вклад.

| Статус критерия | Значение |
|---|---|
| `matched` | Данные достаточны, порог выполнен |
| `not_matched` | Данные достаточны, порог не выполнен |
| `unavailable` | Недостаток покрытия/поддержки/порядка; значение `null` |
| `disabled` | Критерий явно выключен; значение `null` |

Предложения из плана сохранены выключенными: M04 — всплеск относительно
собственного прошлого (та же группа activity, нужен T20); M05 — повторяемые
цепочки с подтверждённой полнотой; M06 — редкость относительно фиксированной
совокупности со сглаживанием; M07 — совместные перелёты в разные дни с поправкой
на популярность рейса, после T18. Включение ещё не реализованных M04–M07
отклоняется. Они не создают фиктивные нули или дополнительные голоса.

## Порядок и объяснения

Вклад группы равен максимальному весу сработавшего критерия этой группы;
число голосов равно числу таких групп. Повтор исходного свидетельства или
несколько связанных счётчиков не добавляют голосов. Веса по умолчанию равны 1.

Основной порядок: **число сработавших групп ↓, балл правил ↓, profile_id ↑**.
Три группы всегда выше двух независимо от весов. Равные баллы разрешаются
стабильным ID. Сам запуск T17 не вычисляет Isolation Forest или граф;
поля IF/комбинации остаются `null` и не участвуют в сортировке. Начиная с
0.10.0 [отдельный T19](model_card.md) обучает IF и сохраняет экспериментальные
таблицы рядом с точной копией основного рейтинга.

Сравниваются профили с одним и тем же включённым набором групп:
`min_available_groups` должен равняться числу включённых групп. По умолчанию
доступны все три. `eligible` требует достаточных данных и ≥1 срабатывания;
`no_matches` означает достаточные данные без срабатываний;
`insufficient_data` — недостаточные данные, даже если часть критериев сработала.
Последние два статуса имеют `rank=null`. В `rankings.parquet` ранги назначаются
всем допустимым профилям; `top50.parquet` содержит только первые 50. Если
подходящих профилей меньше, список не дополняется остальными.

Объяснения по-русски строятся из сохранённых полей: значение и единица,
условие, окно, поддержка, статус и ссылки на учебные сегменты. Числа в тексте
округляются до шести знаков после запятой, в числовых полях — до двенадцати.
M02 сохраняет все сегменты сопоставимых пар, необходимые для проверки
числителя и знаменателя. Даты и аэропорты доступны по этим ID в замороженном
`input/segments.parquet`. Упоминаются возможные обычные объяснения: работа,
регулярные поездки, сезонность. Балл не означает вероятность и не делает
вывода о реальном человеке.

## Файлы и связи

Это отдельный контракт учебной модели, а не замена схем T11–T15.
Авторитетные типы: `models/demo.py` и `models/ranking.py`.

| Файл снимка | Состав / ключ |
|---|---|
| `rule_scores.parquet` | Все профили по ID, баллы, количество групп, доступность, nullable rank |
| `rankings.parquet` | Те же профили: сначала допустимые по рангу, затем остальные по ID |
| `top50.parquet` | Допустимые строки с rank 1…50 |
| `model_explanations.parquet` | `(run_id, profile_id, criterion_id)`, 7 строк на профиль; группы, версии, статусы, значение/порог/единица/оператор, поддержка, вклад, русский текст, evidence ID |
| `features.parquet` | `(run_id, profile_id)`, три учебных признака, окно, покрытие и счётчики формул |
| `feature_coverage.parquet` | `(run_id, profile_id, feature_name)`, доступность, поддержка, причина |
| `input/` | Канонические profiles/segments и проверяемый demo_manifest |
| `config/model.yaml` | Точные байты конфигурации расчёта |
| `model_metadata.json` | Режим, версия, хеши, сортировка, ограничения и состояние будущих компонентов |
| `run_manifest.json` | Параметры запроса и SHA-256 остальных файлов снимка |
| `report.json`, `summary.txt` | Количества, длительность и итог по-русски |

В рейтинговых таблицах есть `data_mode=synthetic_demo`, `ranking_mode=criteria_count`,
`model_version`, `run_id`, окно и `source_coverage`. Evidence-ссылки относятся
только к тому же вымышленному профилю и снимку. Полная история сохраняется во
входных сегментах; критерии выбирают события в своём окне. Карта со стрелками
и датами относится к следующим задачам, а не к этому CLI.

Генерируемые данные, снимки и временные файлы игнорируются Git. Коммитятся
код, конфигурация, тесты и документация. Результат имеет `status=complete_demo`,
`ui_ready=false`, `acceptance=pending_T20_review`: технический проход не заменяет
независимую приёмку. Проверки: [протокол](validation/t17_validation.json).
