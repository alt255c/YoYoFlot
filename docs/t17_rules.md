# T17 · факторы на исходных поездках

Реализация: product/build.py, конфигурация configs/product.yaml. Вход — T13,
неизменные люди и различимые сегменты. Единое окно — min/max известных дат
всего набора; это длительность представленных данных, а не утверждение о
непрерывном наблюдении каждого человека.

| Группа | Формула | Минимальная поддержка / доступность |
|---|---|---|
| M01 Частота | датированные сегменты ×30 / дни общего окна | ≥6 сегментов, принятая идентичность, нет неоднозначных сегментов |
| M02 Быстрые возвраты | соседние обратные A→B→A за 1–2 дня / сопоставимые соседние пары | ≥3 пары; у каждого дня ровно один сегмент, известны оба маршрута, нет недатированных поездок |
| M03 Повторяемость | 1 − уникальные направленные маршруты / пригодные маршрутные сегменты | ≥6 пригодных маршрутов, принятая идентичность и resolved-сегменты |

Общие правила: окно ≥60 дней; известны ≥80% дат, маршрутов/сопоставимых пар
для соответствующего фактора. Для общего рейтинга достаточно одного доступного
и сработавшего фактора. Отсутствие данных по другой группе не отменяет пригодные
наблюдения; оно не приносит баллов и не увеличивает вес известных факторов.
Недоступность сохраняет причину; это не нулевое значение и не фактор.
Два перелёта в один день без точного порядка не превращаются в быстрый возврат.
Дубли segment_id отклоняются, повторные источники уже объединены T13.

## Пороги по исходному набору

Старые демонстрационные пороги 6 перелётов/30 дней, 20% быстрых возвратов,
80% повторов не соответствовали распределению исходного набора. По умолчанию
порог — 95-й процентиль пригодных значений из фиксированного calibration:
первые 32 бита SHA-256(person_id) mod 10 ∈ {6,7}. Нужно ≥100 профилей на
критерий. Нижние положительные границы 0.1/0.01/0.01 не дают нулевому порогу
объявить отсутствие паттерна срабатыванием. Reference size, значение, метод
и итоговый порог сохраняются в explanations и rules.json. Без достаточной
калибровки критерий недоступен, перехода на вымышленный фон нет.

Веса: M01=1, M02=1.5, M03=1. Это явно заданные исследовательские приоритеты;
они не обучены на несуществующих метках. Конфигурационный режим fixed оставлен
для контролируемых экспериментов и регрессионных тестов, а не fallback.

Срабатывание: value ≥ threshold. Вклад: weight × min(3, value/threshold).
В итоговом продукте сортируется сумма вкладов по убыванию, затем person_id.
К базовым факторам добавляются подготовленные факторы исходных документов,
контактов и поездок. Веса берутся из configs/scoring.yaml и сохраняются в снимке.
Факторы с одним основанием не учитываются повторно: выбирается совместимый
набор с наибольшей суммой вкладов. Транзитивная связь через третий фактор
сама по себе не делает два независимых основания одним.
Топ содержит до 50 eligible с ≥1 срабатыванием. Придуманных/нулевых записей нет.
Количество доступных групп сохраняется рядом с количеством срабатываний.
Isolation Forest удалён; пропуски не заполняются вымышленными значениями.

Карта содержит все сегменты выбранного человека, в том числе исключённые из
расчёта отдельных факторов; их статусы видны. Причины воспроизводимы по
сохранённым значениям/порогам. Evidence всегда принадлежит тому же person_id.
