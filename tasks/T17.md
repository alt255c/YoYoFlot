## Результат и файлы

Будущие `src/yoyoflot/models/rule_score.py`, `ranking.py`,
`configs/model.yaml`, `tests/test_rule_score.py`; учебные результаты критериев,
рейтинга и объяснений по [проекту контракта](../docs/product_contract.md).

## Что предстоит

1. Принимать только вымышленный учебный набор с проверенным происхождением;
   реальные персональные таблицы не подавать в расчёт рейтинга.
2. Утвердить минимальный набор P0 из [каталога](../docs/markers.md), допуски
   по окну/покрытию и статусы `matched/not_matched/unavailable/disabled`.
3. Считать независимые группы, а не каждый числовой столбец. M01/M04 и
   связанные счётчики быстрых возвратов не дают повторных голосов.
4. Основной порядок: `matched_criteria_count` ↓, `rule_score` ↓,
   `profile_id` ↑. Зафиксировать версию формулы, веса и ограничение вклада группы.
5. Готовить максимум 50 допустимых профилей с ≥1 сработавшей группой;
   остальные явно имеют недостаточные данные или отсутствие срабатываний.
6. Сохранять фактические значения, пороги, окно, доступность и учебные события.
   Русские причины строить детерминированно по шаблону, без догадок о личности.
7. Не смешивать основной топ с IF/комбинацией и не считать IF отдельным голосом.

## Приёмка

- [ ] Три независимые сработавшие группы выше двух; дублирование одного
  паттерна или исходного свидетельства не меняет число голосов.
- [ ] Перестановка входа и повторный запуск сохраняют порядок и объяснения.
- [ ] Случаи 0/1/49/50/больше 50 подходящих профилей и равные баллы проверены.
- [ ] Null и недостаточное покрытие не создают положительного вклада.
- [ ] Русский текст воспроизводится из сохранённых данных и указывает окно,
  значение, условие и подтверждающие учебные события.
- [ ] Персональные реальные входы отклоняются; пороги проверены T20 до приёмки.
