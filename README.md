# YoYoFlot

Анализ исходного датасета преподавателя: объединённые профили, объяснимый
рейтинг, факторы и карта перелётов. Isolation Forest и обучение ML удалены.
Исходные записи не генерируются, не дополняются вымышленными значениями и не изменяются.

## Ubuntu: полный запуск

В терминале в корне проекта:

```bash
sudo apt update
sudo apt install -y python3 python3-venv
bash build_and_run.sh
```

Проверяемое окружение — Python 3.12. Подготовка полного исходного датасета
занимает существенное время; предусмотрите не менее 50 ГБ свободного места.
Скрипт создаёт `.venv`, устанавливает закреплённые зависимости, скачивает и
проверяет оригинальный архив, обрабатывает все семь источников, рассчитывает
факторы и итоговый рейтинг, проверяет его, сохраняет выгрузки и запускает сайт.

После сообщения `HTTP port 8501` откройте **http://127.0.0.1:8501/**.
Остановка сервера — `Ctrl+C`.

Для следующего запуска готового проекта:

```bash
bash start_web.sh
```

Сайт читает готовый результат и не запускает обучение или обработку исходников.
Чтобы только собрать результат:

```bash
bash build_and_run.sh --build-only
```

Память расчёта факторов можно задать отдельно, например при наличии достаточной
свободной RAM: `bash build_and_run.sh --assessment-memory-limit 4GB`.
Этот параметр не меняет лимит памяти ядра и его кэш. Промежуточные таблицы
факторов сохраняются на диск; лимит DuckDB не ограничивает весь Python-процесс.

Если исходный архив уже скачан:

```bash
bash build_and_run.sh --archive /absolute/path/to/Airlines-All.zip
```

`--core-snapshot` позволяет использовать ранее собранное полное ядро при
совпадении исходных файлов, конфигурации и реализации. Все входы проверяются.
После прерывания повторите команду с тем же `--work-dir`: совместимые этапы
будут использованы повторно. Параметры: `bash build_and_run.sh --help`.

## Результат

- `artifacts/source-product/` — полный продукт для сайта, включая рассчитанные факторы и связи с источниками.
- `artifacts/source-product-report/top50.csv` — тот же топ-50, что на сайте.
- `artifacts/source-product-report/factors.csv` — все факторы, баллы и подтверждающие записи.
- `artifacts/source-product-report/flights.csv` — перелёты выбранных профилей.
- `artifacts/source-product-report/profiles.json` — полные карточки.
- `artifacts/source-product-report/report.md` — отчёт о результате.
- `artifacts/releases/<build-id>/verification.json` — результат проверки итогового рейтинга.

Результаты хранятся в отдельных версиях. Общие пути указывают на последнюю
успешную сборку. Старые результаты сохраняются; при миграции обычного каталога
создаётся каталог `.previous-<hash>` рядом с ним. После новой сборки перезапустите
ранее запущенный сайт: каждый сервер обслуживает одну неизменяемую версию.

## Веса и проверка

Веса находятся в `configs/scoring.yaml`. После изменения выполните сборку,
затем запустите сайт на новом результате. Сайт и экспорт читают одинаковые
сохранённые таблицы; изменение весов не подменяет подготовленные свидетельства.
Балл — сумма выбранных вкладов без повторного учёта общих оснований.
Сортировка: балл по убыванию, затем стабильный ID. Недоступные факторы не дают баллов.

```bash
.venv/bin/python scripts/verify_source_product.py --product artifacts/source-product
.venv/bin/python scripts/audit_source_assessment.py --product artifacts/source-product
```

Проверки выполняются на подготовленном результате исходного датасета.
Исходные единичные фикстуры в `tests/` предназначены только для проверки кода;
сборка и веб никогда не используют их как данные приложения.

Инструкции по публикации и ZIP: [docs/web.md](docs/web.md).
Старые отчёты в `docs/validation/` описывают прежние прогоны и не являются
подтверждением численности или качества новой сборки. Размеченные примеры не
предоставлены; балл не является вероятностью и не даёт измеренной точности классификации.
